# 后置能力交接治理 SOP（2026-11-07）

> **性质**：把“形状先补、行为后置”的能力从**一次性标注**升级为**可执行台账 + 阶段门禁 + 自动检查**。
> **权威台账**：[`docs/待办-后置能力.md`](../待办-后置能力.md)（唯一 ID 来源；代码/本 SOP 只引用，不另建编号）。
> **适用范围**：所有 `TODO(Sx, Dn)` / `NotSupportedException("Deferred to Sx: ... (Dn)")` / 目标阶段明确的未实现能力。
> **维护时机**：阶段开工、阶段收尾、能力重排期、发现 stub 漂移。

---

## 1. 为什么不能只写 spec/plan

仅标注 `Dn` 只能证明“当时知道这件事”，不能保证：

1. 目标阶段真的把它纳入实现；
2. 形状没有被后续重构删掉；
3. 台账“已完成”时代码里已经没有 stub；
4. 目标阶段已过去，但能力被静默遗忘。

所以每条后置能力必须有 **三个锚点 + 一个状态机**：

| 锚点 | 位置 | 作用 |
|---|---|---|
| 形状锚点 | 公共类型/接口/字段/方法 | 证明“形状已经存在”，后续只补行为 |
| 代码锚点 | `TODO(Sx, Dn)` / `NotSupportedException` | 证明“行为仍未实现”，可被脚本扫描 |
| 验收锚点 | 测试文件/测试名 | 证明“以后怎么算做完” |
| 状态 | 台账 `状态` 列 | `未开工 / 进行中 / 已完成 / 重排期` |

---

## 2. 台账字段

`docs/待办-后置能力.md` 的每一行必须包含：

```text
ID | 能力 | pi/pi.net 参考 | 形状锚点（类型/方法/文件） |
验收测试锚点 | S3 状态 | 目标阶段 | 验收口径 | 状态 | 完成提交 | 备注
```

规则：

- `ID` 只增不改；已发布编号不得复用。
- `形状锚点` 必须能定位到 `src/` 或 `tests/` 的具体符号；纯数据/纯文档能力写 `—` 并在备注写原因。
- `验收测试锚点` 必须是可运行的测试名或测试文件；尚未建测试时写目标测试名，阶段开工时落地。
- `状态` 只能取 `未开工 / 进行中 / 已完成 / 重排期`。
- `已完成` 必须同时有：验收测试通过、代码 stub 删除、`完成提交` 填 commit hash。
- `重排期` 必须有用户明确同意的日期与原因，不得由实现 agent 自行改目标阶段。

## 3. 代码标注约定

### 3.1 流式入口的后置失败

```csharp
throw new NotSupportedException(
    "Deferred to S8: deferred responses (D3)");
```

### 3.2 非失败型/字段型后置

```csharp
// TODO(S4, D2): 动态模型目录刷新。
```

### 3.3 约定

- `Sx` 必须是目标阶段（`S4`/`S5`/`S8`/`S9`/`2B` 等）；`Dn` 必须存在于台账。
- 一个能力可以有多个代码锚点；每个锚点都必须带同一个 `Dn`。
- stub 删除时同步删除 `TODO`/`Deferred` 文案；不能只删文案不改状态。
- 不得用“先注释掉类型/方法”代替 stub；形状不可裁剪。

---

## 4. 阶段门禁

### 4.1 开工（Stage Kickoff）

每个阶段 plan 的第一个任务必须是 **“承接后置能力”**：

1. 从台账筛出 `目标阶段 = 当前阶段` 的行；
2. 为每条 Dn 建立行为验收测试（先失败）；
3. 在阶段 spec 的“前置/承接”一节列出 Dn 清单；
4. 更新台账 `状态 = 进行中`，写 owner/计划日期；
5. 如果某条 Dn 不在本阶段实现，必须写“重排期 + 用户批准”，不能静默跳过。

### 4.2 收尾（Stage Exit）

阶段完成门禁必须包含：

```bash
python scripts/check-deferred.py --root . --current-stage S4 --gate exit
```

- 退出码非 0 → 阶段不能标记完成；
- 当前阶段目标 Dn 必须全部 `已完成` 或 `重排期`；
- `已完成` 的 Dn 不得再出现 stub；
- 新出现但未登记的 `TODO(Sx, Dn)` 视为失败。

### 4.3 跨阶段

- `docs/05-教学阶段路线.md` §2.1 的映射表是**阶段归属索引**；
- 新增/重排 Dn 时，先改台账，再改 §2.1，再改本阶段 spec；
- 目标阶段已过但台账仍 `未开工` → 检查脚本失败。

## 5. 自动检查

脚本：`scripts/check-deferred.py`

```bash
# 日常/CI：代码 Dn ↔ 台账一致性
python scripts/check-deferred.py --root . --gate all

# 阶段收尾：额外检查目标阶段是否清账
python scripts/check-deferred.py --root . --current-stage S4 --gate exit
```

检查规则：

1. 扫描 `src/**/*.cs`、`tests/**/*.cs` 中的 `TODO(Sx, Dn)` 与 `Deferred to Sx: ... (Dn)`；
2. 每个代码 `Dn` 必须存在于台账；
3. 台账 `状态=已完成` 的 `Dn` 不得再出现 stub；
4. `--current-stage` 模式下，目标阶段等于或早于当前阶段且状态不是 `已完成/重排期` → 失败；
5. 台账中每个 `Dn` 必须有 `形状锚点` 或 `验收测试锚点`（纯数据类型允许 `— + 备注`）；
6. 输出失败清单，退出码 1；通过退出码 0。

脚本只做“一致性/门禁”，不替 agent 判断行为是否正确；行为正确性由验收测试负责。

---

## 6. 阶段交接卡

阶段收尾时，在下阶段 plan 的“承接”段复制以下最小卡片：

```text
Dn：<ID>
当前形状：<type/method/file>
入口：<调用点>
未实现路径：<stub/TODO 位置>
验收测试：<test file/test name>
目标阶段：<stage>
依赖：<Dn/阶段/外部条件>
风险：<已知坑>
```

台账是长期索引；交接卡是下阶段开工时的阅读材料，两者不能互相替代。

---

## 7. 例外与重排期

- **纯数据类型/纯文档能力**（例如模型目录数据、Telemetry 最小壳）：允许无代码 stub，但必须有形状锚点与验收测试锚点。
- **无法在目标阶段实现**：只能由用户批准重排期；台账写 `重排期`，备注写批准日期、原因、新目标阶段。
- **能力被删除**：必须由用户批准；台账改为 `已取消` 并在决策日志留档，不得直接删行。

## 8. 验收示例

以 `D3 Deferred` 为例：

```text
D3 | Deferred stream/fetch/cancel | pi ... | IDeferredProvider; Models.StreamDeferred/FetchDeferredAsync/CancelDeferredAsync | ModelsCapabilityTests.Deferred_Methods_Are_Deferred_To_S8 | 接口 + stub | S8 | ... | 未开工 | — | ...
```

- S3 收尾：D3 状态 `未开工`，stub 存在 → `--gate all` 通过（因为尚未到 S8）；
- S8 开工：把状态改 `进行中`，建行为测试；
- S8 收尾：删除 stub、测试转绿、填完成提交、状态 `已完成`；
- 再跑 `--current-stage S8 --gate exit` 必须通过。
