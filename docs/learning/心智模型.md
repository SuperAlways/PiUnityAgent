# 心智模型 · 一张图看懂 agent 闭环

> 持续更新；当前是 M1 之前的概念稿。代码落地后按实际事件名/类型名校正。

## 一、一次 prompt 的完整路径

```
用户输入
  │
  ▼
[AgentMessage[]] ──transformContext()──► 裁剪/注入 ──convertToLlm()──► [LLM Message[]]
  │                                                                    │
  │                                                                    ▼
  │                                                              provider 流式
  │                                                                    │
  │                    ┌────────────── text/thinking/toolCall 事件 ────┘
  │                    ▼
  │              assistant message
  │                    │
  │           有 toolCall？
  │            │            │
  │           否            是
  │            │            ▼
  │            │      工具执行（串/并行）
  │            │            │
  │            │      toolResult 消息
  │            │            │
  │            └────► 下一轮 turn？
  │                         │
  ▼                         ▼
agent_end            继续 / 结束
```

## 二、事件顺序（对外可观察）

```
agent_start
  turn_start
    message_start (user)
    message_end   (user)
    message_start (assistant)
    message_update (text/thinking/toolCall delta)
    message_end   (assistant)
    tool_execution_start
    tool_execution_update?
    tool_execution_end
    message_start (toolResult)
    message_end   (toolResult)
  turn_end
  ...（可能多轮）
agent_end
```

## 三、三条关键不变量

1. **工具结果必须跟着工具调用**：不能把 toolResult 切到别的消息前面/后面。
2. **assistant 消息是工具预检的屏障**：`beforeToolCall` 看到的 agent 状态必须已包含发起调用的 assistant message。
3. **`agent_end` 不是最终空闲**：重试、压缩恢复、steering/followUp 都可能再开一轮；需要"真正结束"时等 `agent_settled`（coding-agent 层）。

## 四、失败模式

| 场景 | 表现 | 处理 |
|---|---|---|
| 网络失败/超时 | provider 流终止 | 编码为 error 事件，不抛异常 |
| 用户中止 | `abort` | 当前轮终止；队列消息保留/清空按契约 |
| 工具抛错 | 工具失败 | 转成 `isError` 的 toolResult，不中断循环 |
| 参数 JSON 坏 | toolCall 参数解析失败 | 标记 `argumentsError`，校验失败并回报模型 |
| 上下文溢出 | provider 报 overflow | 2A 的 Compaction 负责压缩后重试 |
