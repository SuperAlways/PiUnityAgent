# SOP 01 · GitHub 推送与代理配置（2026-11-05）

> **适用**：Windows + Git Bash + 本地代理（Clash/Mihomo 等）环境下的本仓库及同类仓库。
> **现象**：浏览器能打开 GitHub，但 `git fetch/push` 报
> `Failed to connect to github.com port 443 after 21118 ms: Could not connect to server`。
> **结论**：不是没网，是 **git 没走浏览器那条代理**；直连 GitHub 443 被阻断。

---

## 一、根因模型

```
浏览器 ──► 系统代理 / 插件代理 ──► 127.0.0.1:7897 ──► GitHub   ✅
git/curl ──► 直连 20.205.243.166:443 ──────────────► 超时     ❌
```

- DNS 正常（`github.com` → `20.205.243.166`），排除 DNS 问题。
- 百度等国内站点直连正常，说明本机有网。
- 本地代理端口在监听，但 **git 未配置代理**（`git config` 无 `http.proxy`，WinHTTP 显示"直接访问"）。
- 浏览器通常使用 WinINET/系统代理或插件代理，git 不会自动继承。

---

## 二、诊断清单（5 分钟）

按顺序执行，确认卡在哪一层：

| # | 检查 | 命令 | 正常表现 | 异常含义 |
|---|---|---|---|---|
| 1 | DNS | `nslookup github.com` | 返回 GitHub IP | DNS 被污染/失败 |
| 2 | 基线连通 | `curl -I --connect-timeout 10 https://www.baidu.com` | HTTP 200 | 本机无网 |
| 3 | 直连 GitHub | `curl -Iv --connect-timeout 10 https://github.com` | 连接成功 | `connect timeout` = 直连被阻断 |
| 4 | 本地代理端口 | `netstat -ano \| grep -E ":(7890\|7897\|1080\|10809\|2080)\b"` | 有 LISTENING | 没开代理 |
| 5 | 系统代理 | `netsh winhttp show proxy` | 看是否配置 | "直接访问" = git 不走代理 |
| 6 | git 代理 | `git config --global --list \| grep -i proxy` | 有配置 | 无配置 = 没走代理 |
| 7 | 代理实测 | `curl -x http://127.0.0.1:7897 -I https://github.com` | HTTP 200 | 端口不对/代理未生效 |

> 本次实测：1 ✅、2 ✅、3 ❌ 超时、4 ✅ `127.0.0.1:7897`（PID 10004）、5 直接访问、6 无配置、7 ✅。

## 三、修复：给仓库单独配代理

> 只影响当前仓库，不改全局；换机器/换端口时同步修改。

```bash
cd <repo>
git config http.proxy  http://127.0.0.1:7897
git config https.proxy http://127.0.0.1:7897
```

验证：

```bash
git config --get http.proxy
git config --get https.proxy
curl -x http://127.0.0.1:7897 -I https://github.com
```

推送：

```bash
GIT_TERMINAL_PROMPT=0 git push -u origin main
```

- `GIT_TERMINAL_PROMPT=0`：没有凭据时快速失败，避免命令挂起等输入。
- 若提示认证失败：检查 Git Credential Manager / PAT；本机未安装 `gh` 时可走 HTTPS + PAT。

## 四、远端状态判断：空仓库 vs 已有提交

推送前先看远端：

```bash
git ls-remote origin
```

| 输出 | 含义 | 动作 |
|---|---|---|
| **空** | 远端还没有任何提交（常见于首次 push 也被网络挡住） | 直接 `git push -u origin main`，本地首提交成为远端首提交 |
| 有 `refs/heads/main` | 远端已有历史 | 先 `git fetch origin`，再决定合并/覆盖 |

### 4.1 远端已有无关历史（例如 GitHub 自动生成的 README）

```bash
git fetch origin
git merge origin/main --allow-unrelated-histories
# 若 README.md 冲突：保留本地完整版
git checkout --ours README.md
git add README.md
git commit -m "merge: 合并远端初始 README"
git push -u origin main
```

> 只有确认远端没有别人/别的自动化在写时，才考虑 `git push --force-with-lease`。

### 4.2 本次实际情况

## 六、回滚 / 取消代理

```bash
# 只取消当前仓库
git config --unset http.proxy
git config --unset https.proxy

# 或改为全局（仅在确认所有仓库都需要时）
git config --global --unset http.proxy
git config --global --unset https.proxy
```

## 七、常见坑

1. **浏览器能访问 ≠ git 能访问**：浏览器走系统/插件代理，git 默认直连。
2. **代理端口会变**：Clash/Mihomo 重启后端口可能从 7897 变为其他；改完配置先 `curl -x` 验证。
3. **`http.proxy` 和 `https.proxy` 都要设**：HTTPS 仓库地址在不同 git 版本/环境下读取的键可能不同。
4. **`git ls-remote` 为空不一定是认证失败**：可能只是远端确实没有提交。
5. **不要无脑设全局代理**：只给需要的仓库配置，避免影响公司内网/其他远端。
6. **不要在没确认远端内容时 force push**：`--force-with-lease` 仍可能覆盖他人的提交。
7. **提交信息**：本仓库提交按项目约定，结尾带 `Co-Authored-By: Claude <noreply@anthropic.com>`。
