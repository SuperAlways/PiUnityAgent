## 0. 背景与问题

原 S3 是最小 chat 注册表：

- `Provider` 是 record + 单个 `StreamFn`；
- `Models` 只有 6 个方法；
- `Model` 缺 `Type/InputLimits/SamplingParams/SamplingParamsByThinkingLevel/Compat/PromptCache`；
- `SimpleStreamOptions` 缺 `fetch`（pi）/ `HttpClient`（pi.net）/ `OnPayload/OnResponse/OnProviderStreamEvent/MaxRetryDelayMs/Identity/Metadata/Env/CacheRetention/Transport/WebsocketConnectTimeoutMs/Telemetry/ToolChoice`；
- 没有认证、动态目录、图片/分类、Deferred 的公共形状；
- `StreamFn` 是 `Task<stream>`，与 pi/pi.net 的同步 LazyStream 形状不同；
- 取消同时存在于 `StreamFn` 参数和 `SimpleStreamOptions`，语义未收口。

按 §1.3，这属于**形状缺失**，不是"行为后置"。本次返工的目标是**补齐公共形状**；行为按阶段实现或 stub。

**v2 追加（2026-11-07）**：通讯层定为 **B 方案**（用户拍板）——`PiUnityAgent.Ai` 自己拥有 Fetch 端口，`UnityLlmTransport` 作为实现/适配方由 Host 消费（见 `docs/07`）。这修正了原 spec 把 pi 的 `fetch` 映射成 `HttpClient?` 单门的问题：Unity 主路径不是 HttpClient，而是 `IStreamingHttpTransport`（UWR）。S3 只定义端口形状，不实现适配器；适配器留给 S13/S4。

## 1. 目标 / 非目标

### 1.1 目标

- 按 pi/pi.net 补齐 `Model`、`SimpleStreamOptions`、`IProvider`、`Models`、Auth、图片/分类/Deferred 的公共类型与成员；
- 形状与行为分层：**能实现的现在实现；不能实现的保留形状并 stub**；
- `StreamFn` / `Models` 改为同步返回 + LazyStream；
- 取消统一为 `StreamOptions.CancellationToken` 单一入口；
- `Models` 公开入口接收原始 `Context`，内部 `normalizeContext`；
- 定义 PiUnityAgent 自有的 Fetch 端口（`FetchFunction` / `FetchRequest` / `FetchOptions` / `IFetchResponse` / `FetchException` / `TransportKind`），对齐 pi `fetch` 形状；
- `Ai` 保持零 `UnityEngine`、零 `UnityLlmTransport` 引用；
- 所有后置行为有登记、有目标阶段、有验收口径。

### 1.2 非目标

- OAuth 登录/刷新/登出行为（S5）；
- 动态模型目录的真实刷新（S4）；
- Deferred fetch/cancel 行为（S8）；
- 图片/分类 provider 的真实实现（2B/后续）；
- Prompt cache 行为（S4/S5）；
- Telemetry 行为（后续扩展）；
- HTTP/SSE 适配器（S4）、Anthropic 适配器（S5）；
- 完整模型目录数据（S4）；
- **Host 适配器**（`UnityLlmTransportFetch` / `HttpClientFetch`）——S13/S4 实现，不在 S3；
- **真实 provider 的 Fetch 请求构造与 SSR/JSON 聚合**——S4/S5 实现。

## 2. 核心决策

| # | 决策 |
|---|---|
| D1 | **形状优先**：公共类型/接口/字段/成员现在补齐；行为可 stub，但不得缺形状。 |
| D2 | **接口优先**：`IProvider` + 可选能力接口；不保留 record + 委托的旧形态。 |
| D3 | **同步流 + LazyStream**：`Stream/StreamSimple` 同步返回 `IAssistantMessageEventStream`；认证/分派失败延迟编码为终态事件。 |
| D4 | **单一取消入口**：只保留 `StreamOptions.CancellationToken`；`StreamFn`/`IProvider` 不再单独收 token。 |
| D5 | **Context 入口**：`Models` 接收 `Context`，内部 `normalizeContext`；`IProvider` 接收 `TranscriptContext`。 |
| D6 | **Auth 类型面完整**：按 pi `auth/types.ts` 补齐公共类型；API Key 行为实现，OAuth 行为 stub。 |
| D7 | **不用默认接口方法**：可选能力用独立接口 + `is` 判断（netstandard2.1/Unity Mono 取舍）。 |
| D8 | **后置登记双落点**：`docs/待办-后置能力.md` 为全量权威；本 spec 附录只放摘要 + 链接。 |
| D9 | **B 通讯端口**：`Ai` 自有 `FetchFunction` 端口；`UnityLlmTransport` 由 Host 适配器消费；`Ai` 不引用通讯组件。 |
| D10 | **端口与适配器分离**：S3 只定义端口形状；适配器与 provider 接线在 S13/S4；S3 不引入 `UnityEngine`。 |

## 3. 公共类型面

### 3.1 Model 与辅助类型

`Model` 保留现有字段，新增：

| 字段 | 类型 | 默认 |
|---|---|---|
| `Type` | `ModelType` | 由派生类型固定（Model=Chat / ImageModel=Image / ClassifierModel=Classifier） |
| `InputLimits` | `ModelInputLimits?` | `null` |
| `SamplingParams` | `JsonObject?` | `null` |
| `SamplingParamsByThinkingLevel` | `IReadOnlyDictionary<ModelThinkingLevel, JsonObject>?` | `null` |
| `Compat` | `JsonObject?` | `null` |
| `PromptCache` | `ModelPromptCache?` | `null` |

`Model` 不再 standalone：公共字段上移到 `ProviderModel` 基类；`Model` / `ImageModel` / `ClassifierModel` 分别对应 chat / image / classifier。

### 3.3 Context 规范化

- `Models.Stream/StreamSimple` 接收 `Context`；
- `TranscriptNormalization.NormalizeContext(Context)`：把 `SystemPrompt` / `Tools` 折成前导 `SystemMessage`，`Timestamp = 0`；
- 空 prompt + 空 tools → 不插入 system 消息；
- 原消息顺序不变；
- `IProvider` 只接收 `TranscriptContext`。

### 3.8 LazyStream

新增 `Events/LazyStream.cs`：

```csharp
public static class LazyStream
{
    public static IAssistantMessageEventStream Run(
        Model model,
        Func<Task<IAssistantMessageEventStream>> factory,
        TelemetrySpan? telemetry = null);
}
```

语义：

1. 立即返回代理流，不执行 factory；
2. 首次迭代 / `WaitForDoneAsync` 时执行 factory，且只执行一次；
3. factory 返回的流事件被转发；
4. factory 抛 `OperationCanceledException` → 终态 `Error(Aborted)`；
5. 其他异常 → 终态 `Error(Error)`，`ErrorMessage` 为异常消息；
6. 代理流的 `Partial` 跟随上游；
7. 结束后 `Push`/`End` 行为与 S2 一致。

### 3.9 Faux 迁移

- `FauxProvider` 实现 `IProvider`（或暴露 `IProvider Provider { get; }` 为 `StaticProvider`）；
- `StreamAsync` 改为同步返回流：内部启动 `EmitAsync` fire-and-forget；
- 取消：只读 `options.CancellationToken`；
- 模型/选项/脚本队列/确定性逻辑保持不变；
- `Faux` 辅助函数保持；`Factory.Create` 命名保持。

### 3.10 Fetch 端口（B 方案）

新增 `Types/Fetch.cs`（或按类型拆分），定义 pi `fetch` 的 C# 等价物；**完整形状与语义见 `docs/07-通讯层集成契约.md` §二，本节只钉 S3 落点**。

```csharp
public delegate Task<IFetchResponse> FetchFunction(
    FetchRequest request,
    FetchOptions? options,
    CancellationToken cancellationToken);

public sealed record FetchRequest(
    string Method,
    string Url,
    FetchHeaders Headers,
    ReadOnlyMemory<byte> Body)
{
    public Func<CancellationToken, Task<Stream>>? BodyFactory { get; init; }
}

public sealed class FetchHeaders : Dictionary<string, string?> { /* 大小写不敏感；null 抑制默认头 */ }

public sealed record FetchOptions
{
    public TransportKind? Kind { get; init; }
    public TimeSpan? ConnectTimeout { get; init; }
    public TimeSpan? FirstByteTimeout { get; init; }
    public TimeSpan? IdleTimeout { get; init; }
    public int? MaxResponseBytes { get; init; }
    public IReadOnlyDictionary<string, string>? Env { get; init; }
    public string? SessionId { get; init; }
}

public interface IFetchResponse : IAsyncDisposable
{
    int StatusCode { get; }
    FetchHeaders Headers { get; }
    Stream Body { get; }
    void Abort();
}

public enum FetchErrorKind
{
    Connect, Tls, Proxy, Protocol, FirstByteTimeout,
    IdleTimeout, Cancelled, Aborted, Overflow, Unsupported
}

public sealed class FetchException : Exception
{
    public FetchErrorKind Kind { get; }
    public int? StatusCode { get; init; }
    public FetchHeaders? Headers { get; init; }
    public string? ErrorBody { get; init; }
    public bool IsRetryable { get; init; }
}
```

规则：

1. **只吐字节**：不判断 `[DONE]`、不拼 JSON、不聚合 `tool_calls`/`usage`/`stopReason`。
2. **响应头前失败** → `FetchException`；**拿到 HTTP 状态（含 4xx/5xx）** → 返回 `IFetchResponse`，provider 决定读错误体/抛协议错误。
3. **取消** → 中止底层连接；`Body.ReadAsync` 尽快结束；`Abort()` 幂等。
4. **`Ai` 零 `UnityEngine`、零 `UnityLlmTransport` 引用**；适配器（`UnityLlmTransportFetch`）在 S13/S4，不在 S3。
5. `StreamOptions.Fetch == null` 时用 provider 构造时注入的默认 `FetchFunction`；`Models` 不持有全局 fetch；provider 也无默认 → 终态 `Error`（不抛）。
6. `HttpClient?` 不再出现在 `StreamOptions`；桌面/.NET 用 `HttpClientFetch`（S4/Hosts.Net8）实现同一端口。

## 9. 风险

1. **改动面大**：Provider/Models/Faux/测试全部 breaking；按迁移顺序分步保持可编译。
2. **Auth 类型面大**：只补 pi 公共形状，不发明；OAuth 行为后置。
3. **LazyStream 一次性/线程语义**：必须有"只启动一次"、提前等待、结束后 Push 的测试。
4. **netstandard2.1/Unity**：不用 DIM；**Unity 流式主路径 = UWR（UnityLlmTransport Phase 2 已三版本实机验证）；HttpClient 在 Unity Mono/IL2CPP 下不作流式承诺**；Channels 已有依赖。
5. **stub 泛滥**：每个 stub 必须对应登记表 ID；评审逐个核对。
6. **端口/适配器漂移**：Fetch 端口与 `IStreamingHttpTransport` 是两份形状，必须有适配器契约测试守住；适配器不在 S3，S13/S4 实现。
7. **无默认 Fetch**：宿主未注入时 provider 终态 `Error`，不抛；测试覆盖。
8. **2022.3 缺口**：Phase 2 矩阵为 2021.3/6.3/6.6；太吾实际 `2022.3.62f2`，S4 实机前补冒烟或明确前向兼容假设。

## 12. Phase 2 通讯事实（版本锁）

> 来源：`UnityLlmTransport/docs/spike/phase2-results.md`；版本锁 `87db637`（2026-11-07）。

- Unity `2021.3.45f1c2` / `6000.3.28f1` / `6000.6.8f1` × Mono/IL2CPP = **6 组，每组 15/15 `|OK|`**；
- UWR 真流式、取消=Abort、首字节/空闲超时、溢出、500 错误体、TLS、重定向、Abort 后读侧干净均通过；
- gzip：UWR 自动解压但响应头仍标 `Content-Encoding: gzip`；适配层 magic 嗅探，`Compression` 能力保留；
- 显式代理在 UWR 下 `Unsupported`；系统代理可用；
- `ConnectTimeout` 在 UWR 下实际约束到响应结束（实现偏离，Phase 2 spec 已记）；
- U11 只证明读侧干净；引擎层 `ReceiveData` 残留计数直证推迟 Phase 3；
- **2022.3.62f2（太吾实际版本）不在矩阵内** → S4 实机前补冒烟或明确前向兼容假设。

本 spec 的 Fetch 端口不依赖 UWR 实现；Phase 2 结论只用于锁定“Unity 主路径可用”与“适配器目标实现”。
