# 阶段偏离审查 SOP（2026-11-08）

> **性质**：每个阶段实现完成后、合并/交付前，对“公共形状 / 行为 / wire / 生态”做一次独立偏离审计。
> **执行者**：控制器（本会话）另派一个**独立 subagent**；审计者只读代码与参考源，只写审计报告，不改实现。
> **上位规则**：[`docs/03-开发方法-拆解学习与移植约定.md`](../03-开发方法-拆解学习与移植约定.md) §1.3 阶段一对齐总则。
> **配套规则**：[`docs/SOP/后置能力交接治理-SOP-2026-11-07.md`](后置能力交接治理-SOP-2026-11-07.md)（只负责 C 类行为后置）。
> **最近适用**：S3 v2（2026-11-08，已合 main，回溯审计）。

---

## 1. 为什么需要单独审计

代码 review 主要看“写得对不对、测试够不够”；偏离审查专门回答：

1. pi 原版有的公共形状，我们是不是都有？
2. 我们改的东西，到底属于 A/B/C/D 哪类？
3. spec 的三方偏离表是不是**真的**和代码一致？
4. 有没有“不是 A，却悄悄简化了形状”的情况？

**spec 的三方偏离表本身不是真相源，只是待审计的声明。** 审计必须回到 pi 原版和 pi.net 源码核对。

## 2. 参考对象与优先级（不可颠倒）

| 优先级 | 对象 | 用途 |
|---|---|---|
| 1 | pi 原版 `v1.5.0` / `f9a263655` | 行为、形状、默认值、事件顺序、失败模式、wire 语义的**唯一真相源** |
| 2 | pi.net `main` / `2d6757b` | 只回答“同一个 TS 特性在 C# 里怎么写”；与 pi 冲突时以 pi 为准 |
| 3 | UnityLlmTransport docs（版本锁 `4c0cc4b` / `0.6.0`） | 只管通讯事实：流式/取消/超时/平台矩阵；不定义 provider 协议 |
| 4 | Unity `2022.3.62f3c1` + netstandard2.1 | 只有这类硬约束可以作为 A 类偏离理由；游戏实际 `2022.3.62f2` 的最终验收单独做 |

> 审计者必须明确写下本轮使用的 tag/commit/版本锁；版本未确认时先记录“未确认”，不得凭记忆判断。

## 3. 审计范围

### 必审

- **公共形状**：类型、接口、字段、可选成员、默认值、继承/联合表达；对比 pi 原版公共 API，pi.net 只作写法参考。
- **行为语义**：事件顺序、终态、错误/取消、重试、空值、默认行为。
- **wire 契约**：枚举字符串、JSON 字段名、header、SSE/NDJSON 语义。
- **生态边界**：TFM、Unity 主线程、传输层、依赖方向、AOT/2L 限制。

### 不在本审计范围

- 普通代码质量、命名、性能、测试是否充分 → 由常规 code review 负责。
- 后置行为是否实现 → 由 Dn 台账和阶段门禁负责；本审计只检查 **C 类形状是否保留、Dn 是否登记**。

---

## 4. 偏离分类

| 类别 | 含义 | 审计判定 |
|---|---|---|
| **A** | 语言/生态强制（C# 无 union、AbortSignal→CT、AsyncIterable→IAsyncEnumerable、netstandard2.1、Unity、无 DIM） | 允许；必须写替代方案与代价 |
| **B** | 借鉴 pi.net 的 C# 表达 | 允许；不得改变 pi 语义；pi.net 偏离 pi 时不能照抄 |
| **C** | 行为后置，**形状必须保留** | 允许；必须有 Dn、形状锚点、验收测试、目标阶段 |
| **D** | 我们主动加固（收益/代价明确） | 允许但需明示；不能用来掩盖功能缺失或形状裁剪 |
| **Shape gap** | 不是 A/B/C/D，却删了/简化了公共形状或改了语义 | **不允许**；Critical/Important 发现，修或由用户明确批准为 D 并登记 |

判定口诀：

```text
先问 pi 有没有这个公共形状/语义？
  有 → 我们有没有？没有 = shape gap
  有 → 我们有但行为未实现 = C（Dn）
  有 → 我们改了表达但语义等价 = A/B
  没有 → 我们主动加 = D（说明收益/代价）
```

## 5. 每阶段执行流程

### 5.1 阶段收尾触发

阶段代码完成、Release/单测/Dn 门禁通过后，**合并或交付前**执行：

1. 控制器记录审计范围：`base..head`（阶段分支起点到当前 HEAD）。
2. 从 `docs/03` §1.3 复制审计约束，从阶段 spec 取三方偏离表和公共形状清单。
3. 派一个**独立 subagent**（建议最强模型；不得与实现者为同一会话）做只读审计。
4. 审计者写报告到 `docs/audits/<stage>-deviation-audit-<yyyy-mm-dd>.md`。
5. 控制器按报告分类处理：
   - **Shape gap / Critical**：修复，或由用户明确同意登记为 D；否则不得合并/交付。
   - **未登记偏离**：补 spec §8 行（pi/pi.net/我们/类别/原因/代价）。
   - **C 类缺口**：补 Dn 台账，形状/验收测试/目标阶段齐全。
   - **误报**：控制器带证据驳回，记录在报告末尾。
6. 修复后重新派**新的独立审计 subagent**复核；不复用原审计者的结论。
7. 审计报告链接写入阶段 spec/plan/`docs/05`，作为阶段完成材料。

### 5.2 已合并阶段（回溯）

若阶段已合并（例如 S3 v2），仍执行同样审计；报告结论写入 `docs/audits/`，后续阶段开工前先处理 Shape gap / 未登记项。

## 6. 审计者输出模板

报告必须包含：

```markdown
# <Stage> 偏离审查（<date>）

> 审计者：<subagent 模型/会话>
> 参考版本：pi <tag/commit>；pi.net <commit>；UnityLlmTransport <commit>
> 范围：<base>..<head>
> 结论：PASS / PASS_WITH_REGISTERED_DEVIATIONS / FAIL

## 1. 公共形状矩阵

| 区域 | pi 原版 | pi.net | 我们 | 判定 | 类别/缺口 |
|---|---|---|---|---|---|

## 2. 行为 / wire / 生态
（默认值、事件顺序、失败模式、取消、wire 字符串、TFM）

## 3. 未登记偏离 / Shape gap
（每条 file:line + 为什么不是 A/B/C/D + 建议）

## 4. C 类 Dn 检查
（Dn 形状锚点/验收测试/目标阶段是否齐）

## 5. 必需动作
- [ ] ...
## 6. 审计者附注
（误报、无法验证项、版本未确认项）
```

审计者必须给 `file:line` 证据；不得只写“看起来一致”。

## 7. 审计 subagent prompt（控制器复制使用）

```text
你是独立偏离审计者，不是实现者。只读代码/文档/参考源，不改代码、不改 index/HEAD/分支。
参考顺序：pi 原版（行为/形状唯一真相源）→ pi.net（只作 C# 写法参考）→ UnityLlmTransport docs（仅通讯事实）→ Unity/netstandard2.1（仅 A 类硬约束）。
不要相信阶段 spec 的三方偏离表；它是待核对的声明。

输入：
- 阶段 spec：<path>
- 阶段 plan：<path>
- 对齐规则：docs/03-开发方法-拆解学习与移植约定.md §1.3
- 代码/diff：<base>..<head>；<diff file>
- pi 参考：<pi paths>；pi.net 参考：<pi.net paths>
- 台账：docs/待办-后置能力.md

任务：
1. 枚举阶段涉及的公共类型/接口/字段/方法/默认值，逐项与 pi 原版对比；pi.net 只用于 C# 表达。
2. 检查行为语义、事件顺序、失败/取消、wire 字符串、生态边界。
3. 对每个差异判定 A/B/C/D 或 Shape gap；记录 file:line 与代价。
4. 核对 C 类是否在台账有形状锚点/验收测试/目标阶段。
5. 核对 spec §8 每一行是否真的对应代码；找“未登记偏离”。
6. 写报告到 docs/audits/<stage>-deviation-audit-<date>.md；结论只能是 PASS / PASS_WITH_REGISTERED_DEVIATIONS / FAIL。

禁止：修复代码、跑实现者测试、凭记忆猜 pi 行为、把 spec 表当真相源。
```

---

## 8. 门禁与完成定义

阶段算“可合并/可交付”必须同时具备：

- [ ] 阶段 spec 有三方偏离表，且每行与代码一致；
- [ ] 审计报告已产出、结论非 FAIL；
- [ ] Shape gap 已修复，或用户明确批准登记为 D；
- [ ] 未登记偏离已补进 spec §8；
- [ ] C 类 Dn 台账完整；
- [ ] 修复后的复核由新的独立审计者完成；
- [ ] 审计报告路径写入阶段 spec/plan/`docs/05`。

任何一项不满足，不得合并/交付；已合并的阶段在下一阶段开工前清偿。

---

## 9. 维护

- 新阶段开工时先把本 SOP 和 `docs/03` §1.3 纳入阶段 plan 的第一个任务。
- 审计报告只追加、不覆盖；误报在报告末尾写明证据。
- 审计模型/会话记录在报告头；不要用实现者自己的总结替代审计。
- 版本变化（pi tag/pi.net commit/UnityLlmTransport commit）时重新审计受影响的形状。
