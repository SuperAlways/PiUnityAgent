# 第一部分 · 开工前：概念与决策

## 1. 它解决什么问题

模型只认四种角色：`system`、`user`、`assistant`、`toolResult`。
但 agent 还要表达：文本、思考、图片、工具调用、工具结果、用量、停止原因、错误。

**消息与内容模型就是这层共同语言**：

- provider 用它发送/解析；
- agent loop 用它读懂"模型要调哪个工具"；
- 会话/压缩/日志用它序列化。

没有它，每个 provider、每个工具、每个会话格式都会各造一套。

## 2. 一条消息的旅程

```
SystemMessage（prompt + 工具声明）
        │
        ▼
UserMessage（文本 / 文本+图片）
        │
        ▼
AssistantMessage（文本 / 思考 / 工具调用 + usage + stopReason）
        │
        ├─ 没有 ToolCall → 本轮结束
        └─ 有 ToolCall
                ▼
        ToolResultMessage（toolCallId + content + isError）
                │
                ▼
        下一轮 AssistantMessage
```

`Context`（调用方输入，可简写 `systemPrompt` / `tools`）与 `TranscriptContext`（规范化后，prompt/工具声明折进 system message）要分开。

## 3. 三条关键不变量

1. **角色与内容块匹配**
   - system：文本；
   - user：文本/图片；
   - assistant：文本/思考/工具调用；
   - toolResult：文本/图片，且必须有 `toolCallId`、`toolName`、`isError`。

2. **工具结果必须能追溯到工具调用**
   - `ToolResultMessage.ToolCallId` 必须对应某个 `ToolCall.Id`；
   - 不允许出现没有调用方的工具结果。

3. **失败是数据，不是异常**
   - 模型/网络失败：`StopReason.Error` / `Aborted` + `ErrorMessage`；
   - 工具失败：`IsError = true`；
   - 参数 JSON 坏：`ArgumentsError` 有值，`Arguments = {}`；
   - 截断：`StopReason.Length`；
   - 推理被过滤：`ThinkingContent.Redacted = true`，签名保留。

## 4. 失败模式

| 场景 | 表现 | 处理 |
|---|---|---|
| 坏 JSON 工具参数 | `ArgumentsError` 有值，`Arguments = {}` | 校验失败 → 错误 toolResult 回给模型 |
| 请求被中止 | `StopReason.Aborted` | 不重试；保留已产生消息 |
| 输出被截断 | `StopReason.Length` | 记录；S11 压缩/重试处理 |
| provider 报错 | `StopReason.Error` + `ErrorMessage` | 编码为消息/事件，不抛到调用方 |
| thinking 被过滤 | `Redacted = true` | 保留签名，按 provider 规则回放 |
| 工具结果缺 `ToolCallId` | 非法消息 | 校验拒绝 |
| 空 content | 合法但无用 | 上层决定是否重试 |

## 5. 可调旋钮

| 旋钮 | 影响 | 备注 |
|---|---|---|
| `maxTokens` | 单次输出上限 | `Model.maxTokens` / 请求选项 |
| `thinkingLevel` | 推理预算 | `off`…`max`；provider 可能不支持 |
| `samplingParams` | 温度/采样 | 模型默认 + 请求覆盖 |
| `toolChoice` | 是否允许/强制工具 | `auto` / `none` |
| `stopReason` 处理 | 是否重试/压缩 | 由 agent loop 决定 |

## 6. TS → C# 映射

| TS | C# |
|---|---|
| `Message` 联合 | `abstract record Message` + 四个派生 record |
| `ContentBlock` 联合 | `abstract record ContentBlock` + 四个派生 record |
| `content: string \| blocks` | `required MessageContent`（`Text`/`Blocks` 联合）+ `MessageValidation` |
| `JsonObject` | `System.Text.Json.Nodes.JsonObject` |
| `number`（时间戳） | `long`（Unix ms） |
| `ToolResultMessage<T>` 条件类型 | 非泛型 + `object? Details` |
| 字符串字面量联合 | `enum` + 自定义 `JsonConverter`（wire 往返） |
| 可选字段 `?` | `T?` / nullable；必填字段用 `required`（polyfill） |

命名规则：类型名与上游一致；C# 只做 PascalCase、`Async` 后缀、`I` 前缀、union→record 的机械变换。

| 能力 | 处理 |

| `ClassifierContext` / 分类 API | **类型保留**；实现后置 |

# 第二部分 · 实现后：代码、测试与差异

## 10. C# 设计取舍

| 决策 | 选择 | 理由 |
|---|---|---|
| union 类型 | 抽象 record + 派生 | C# 没有 discriminated union |
| `string \| blocks` | `MessageContent` 联合（`Text`/`Blocks`）+ 自定义 `JsonConverter` | 读/写按 JSON 实际形状（string vs array）分派；null 归一为空 blocks |
| `ContentBlock` 多态 | `[JsonPolymorphic]`（判别符 `type`）+ `[JsonIgnore] Type` | wire 靠 `type` 判别；C# 侧 `Type` 属性只作便利读取，参与 JSON 会与判别符冲突 |
| 必填字段 | `required` + `RequiredMemberAttribute` polyfill | 构造期强制，不再靠运行时校验兜底 |
| `ToolResultMessage<T>` | 非泛型 + `object? Details` | 避免泛型污染；Details 不预设 JSON 形状 |
| `StopReason` / `ThinkingLevel` | enum + 自定义 `JsonConverter` | wire 与 pi 一致；未知 wire 值抛错而非静默 |
| `init` / record | `IsExternalInit` + `RequiredMembers` polyfill | netstandard2.1 没有这些类型 |
| `JsonObject` | `System.Text.Json.Nodes` | 与 provider JSON 参数对应 |

## 13. 与上游 / Pi.NET 的差异

- **上游**：类型名一致；
- **我们**：`string | blocks` 折成 `MessageContent` 联合；必填字段用 `required`；`ContentBlock.Type` 加 `[JsonIgnore]`（wire 用 `type` 判别符）；`ToolResultMessage` 非泛型 + `object? Details`；`StopReason`/`ThinkingLevel` 用自定义 enum converter；图片输入/输出用 marker interface；
- **Pi.NET**：只参考 C# 写法，不照抄字段；冲突以上游为准。
