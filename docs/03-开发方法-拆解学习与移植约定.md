# 03 · 开发方法：拆解、学习与移植约定（2026-11-04）

> **状态**：方法约定 v1.1（2026-11-05）。
> **用途**：规定本项目的开发节奏、参考源顺序、讲解交付物与移植纪律。
> **适用**：所有参与本项目的实现者（人或 AI）。
> **一句话**：**以最新原版 pi 为行为真相源，先拆解再重做；Pi.NET 只作 C# 语言映射参考；每个开发循环都必须产出"能讲清的心智模型 + 可运行代码 + 可调优说明书"。**

---

## 一、目标与角色

### 1.1 两层目标

| 目标 | 内容 |
|---|---|
| **学习（更根本）** | 拆解工业界最强的 agent 项目（pi），重做成 C#；通过"拆解→讲解→实现→对照"建立坚实心智模型，能决策、能调优 |
| **产品（自然结果）** | 一个 netstandard2.1 的 C# agent 底座（pi-ai + pi-agent-core），个人可用，并开源给 C# 游戏 mod 开发者与游戏厂商 |

### 1.2 三个参考角色

| 角色 | 是谁 | 怎么用 | 优先级 |
|---|---|---|---|
| **行为真相源** | 最新原版 pi（TypeScript） | 语义、协议、循环、事件顺序、失败模式、可调参数 | **第一** |
| **C# 语言映射参考** | Pi.NET（net9/net10，本地 `pi-study/pi.net`） | 只看 TS 与 C# 特性不同时它怎么处理 | **第二** |
| **产物** | 本项目的 netstandard2.1 重构 | 语义等价 + C# 惯用法 + Unity 可用 | — |

> **"先看两边"的固定顺序：先读最新原版 pi，再看 Pi.NET。** 反过来的风险是：把 Pi.NET 的实现当作行为标准，而它本身可能偏离上游、或有 port 缺陷。

## 二、参考源纪律（强制）

1. **先原版，后 Pi.NET。** 每个模块动工前，先读原版 pi 的源码/文档，弄清"它做什么、为什么、边界在哪"；然后再看 Pi.NET "用 C# 怎么表达"。
2. **版本打钉。** 每个模块开工前记录：
   - 原版 pi：tag + commit（本地参考已同步 v1.5.0 / f9a263655 / 2026-11-02；**开发当日仍应先确认最新 tag**）；
   - Pi.NET：版本 + 对应上游 commit（当前 `main 2d6757b`；最新 tag `v1.4.5` + 40 commits；docs 对齐上游 v1.5.0）。
   - 记录位置：模块讲解卡 + 决策日志。
3. **冲突时以原版 pi 为准。** Pi.NET 与 pi 行为不一致时，按 pi 实现，并在决策日志登记差异。
4. **不直接抄 Pi.NET 的业务逻辑。** 它只回答"这个 TS 特性在 C# 里怎么写"；协议、状态机、事件顺序、错误契约仍以 pi 为准。
5. **不盲目追最新。** 原版 pi 迭代快；每个批次只对齐一个明确 tag，发现上游漂移先记录，不随手跟。

### 2.5 参考源同步与版本打钉（每个模块/批次开工前）

**频率**：每个模块或批次开始时同步一次；模块进行中不换版本。

**原版 pi**：

```bash
git -C pi-study/pi fetch --tags --prune
git -C pi-study/pi tag --sort=-v:refname | head -5
git -C pi-study/pi log -1 --date=short --format="%h %ad %s"
```

- 若本地不是最新 tag：检出最新 tag，或明确固定某个 tag（二选一，写进版本卡）。
- 记录：tag / commit / 日期。

**Pi.NET**：

```bash
git -C pi-study/pi.net fetch --tags --prune
git -C pi-study/pi.net describe --tags --abbrev=0
git -C pi-study/pi.net log -1 --date=short --format="%h %ad %s"
```

- 读 `docs/migration-execution-status.md` 的当前口径（对齐到哪个上游版本、哪些包未完成）。
- 记录：版本 / commit / 日期。

**网络**：参考仓库不继承本仓库代理时，单独配置或命令内指定：

```bash
git -c http.proxy=http://127.0.0.1:7897 -C pi-study/pi fetch --tags
```

**版本卡**：写入讲解卡 §0 与 `PORTING.md`；同时记录"上游领先/落后本模块多少"。同步结果不确定时，宁可固定旧 tag，也不要边写边换。

## 三、每个模块的开发循环

```
选模块/定边界
  → 同步参考源并打钉（§2.5）
  → 读原版 pi（输入/输出/不变量/事件顺序/失败模式/可调参数）
  → 写讲解卡（先讲给你听，再动手）
  → 查 Pi.NET（只解决语言映射）
  → spec/plan（superpowers）
  → TDD 实现（Faux provider 先行）
  → 对照验证（golden transcript / 行为 diff）
  → 复盘 + 更新教学文档/心智模型/调优手册
  → 门禁
```

### 3.0 三方对照（贯穿）

| 顺序 | 看谁 | 回答什么 |
|---|---|---|
| 1 | **原版 pi** | 行为、不变量、事件顺序、失败模式、可调参数 |
| 2 | **Pi.NET** | 同一个 TS 特性在 C# 里怎么写、它踩过什么坑 |
| 3 | **我们的 2.1 实现** | 语义等价、Unity 可用、单测通过 |

- **冲突以原版 pi 为准**；Pi.NET 的偏离登记在讲解卡 §8。
- 我们的偏离（裁剪、拆分、命名、2.1 妥协）登记在 `PORTING.md` 与决策日志。
- 不要求逐字节一致，要求消息序列、工具调用、事件顺序、终止条件语义一致。

### 3.1 选模块

- 一次只做一个可独立讲清的模块（例如"流式事件协议""工具执行""压缩"）。
- 模块边界写进讲解卡；跨模块依赖先列出来，不边做边扩。

### 3.2 读原版 pi

必须回答这六个问题，写进讲解卡：

1. 输入是什么、输出是什么？
2. 状态机/数据流怎么走？
3. 三条关键不变量是什么？
4. 失败模式有哪些（网络、超时、中止、错误参数、空结果）？
5. 事件顺序是什么（谁先谁后，哪些是屏障）？
6. 有哪些可调参数（阈值、并发、预算、超时）？

### 3.3 讲解卡（先讲再做）

- 在每个模块动工前，用一页纸讲给用户听：图 + 关键决策 + 与 C# 的映射。
- 用户确认理解后再进入实现；实现中发现理解有误，回头改讲解卡。

### 3.4 查 Pi.NET

- 只查"语言映射"：union→record、AbortSignal→CancellationToken、AsyncIterable→IAsyncEnumerable、typebox→JSON Schema、`Lock`/`Task.WhenEach` 等 net9 特性的替代。
- 记录 Pi.NET 的取舍与坑（例如它依赖 net9 API、全量 provider 带来的复杂度）。

### 3.5 spec / plan / TDD

- 遵循项目既有 superpowers 流程：spec → plan → TDD。
- **Faux provider 先行**：先让循环在无网络、无密钥下可测，再接真实 provider。
- Core 必须有单测；宿主适配靠契约 + 实机。

### 3.6 对照验证

- 用同一组场景，在以下三者上跑并对比事件流：
  1. 原版 pi（TS，行为基准）；
  2. Pi.NET（C# 参考）；
  3. 我们的实现。
- 对比维度：消息序列、工具调用顺序、事件顺序、终止条件、错误编码。**语义一致即可，不要求逐字节一致。**
- 对照结果写入模块讲解卡的"差异"一节。

### 3.7 复盘

- 每个批次结束做一次复盘：哪里理解错了、哪里 C# 表达别扭、哪些参数需要调。
- 复盘产出：更新心智模型文档 + 调优手册 + 决策日志。

### 3.8 门禁（模块完成定义）

一个模块算完成，必须同时具备：

- [ ] 代码可运行、Core 单测全绿；
- [ ] 参考源同步记录（版本卡，§2.5）；
- [ ] 讲解卡（§四模板）；
- [ ] 教学文档（`docs/learning/` 对应篇章，§五）；
- [ ] 对照记录（与原版 pi / Pi.NET 的差异）；
- [ ] 决策日志（如有取舍）；
- [ ] 调优手册条目（如有旋钮）；
- [ ] 无 net9/net10 专有 API（netstandard2.1 可编）。

## 五、教学文档体系（持续更新，留在仓库里）

教学不是聊天里的附赠品，而是与代码一起演进的一等交付物。分两套：

### 5.1 `docs/learning/` —— 教人

```
docs/learning/
├─ 00-导读.md                 # 怎么读这个移植、怎么用这套文档
├─ 01-从零搭建：最小 agent 闭环.md
├─ 02-事件流与流式协议.md
├─ 03-工具执行与并发.md
├─ ...
├─ Q&A.md                     # 用户提问 + 回答 + 纠正，持续追加
└─ 心智模型.md                 # 状态机/事件时序/上下文组装图
```

- 每篇结构：**它解决什么问题 → 数据流/状态机 → 三条不变量 → 失败模式 → TS/C# 差异 → 调优 → 小练习**。
- `Q&A.md` 记录用户的疑问、误解与纠正；这是后人最有价值的部分。
- 每个模块的 DoD 包含对应教学篇章；**没有教学文档不算完成**。
- 文档留在仓库里，跟代码一起提交、一起演进，不放在聊天记录里。

### 5.2 `docs/model/` —— 查证

```
docs/model/
├─ 00-总览.md            # 一张图：消息→上下文→模型→工具→回写
├─ 01-agent-loop.md      # 状态机、turn 生命周期、事件顺序
├─ 02-events.md          # 流式事件协议、partial 语义
├─ 03-tools.md           # 工具契约、并发、前后钩子、错误
├─ 04-context.md         # 上下文组装、system message、工具声明
├─ 05-session-compaction.md
├─ 06-skills-extensions.md
└─ 07-providers.md       # provider 差异、认证、usage/成本
```

每篇固定结构：**一张图 + 三条不变量 + 失败模式 + 调优旋钮**。不抄书，只写"我们自己的理解"。

> 两套的分工：`learning/` 负责"为什么、怎么想、怎么练"；`model/` 负责"一页纸查证"。讲解卡（§四）是模块级入口，写完沉淀到这两套里。

## 七、调优手册（随模块积累）

至少覆盖这些旋钮：

| 旋钮 | 影响 | 典型默认 | 症状与调法 |
|---|---|---|---|
| 最大轮次 / turn 上限 | 成本、卡死风险 | 待定 | 循环不收敛 → 降上限 + 检查工具结果 |
| 工具执行模式 | 延迟、顺序、副作用 | parallel | 有写操作/顺序依赖 → sequential |
| 工具并发数 | 延迟、游戏主线程压力 | 待定 | 卡帧/主线程争用 → 降并发 |
| 压缩阈值 | 上下文成本、记忆连续性 | 待定 | 频繁超限 → 降阈值；丢失关键事实 → 升阈值 |
| thinking level | 质量、成本、延迟 | 按模型 | 简单任务降档；复杂规划升档 |
| 超时 / 重试 | 稳定性、玩家等待 | 待定 | 超时频繁 → 查网络/模型；重试过多 → 降次数 |
| token 预算 | 成本 | 待定 | 超预算 → 压缩/裁剪工具结果 |
| max tokens | 单次输出长度 | 按模型 | 截断 → 升；成本高 → 降 |
| 工具结果截断 | 上下文大小 | 待定 | 大结果撑爆上下文 → 截断 + 结构化摘要 |

## 八、移植范围与 C# 映射

### 8.1 范围

| 层 | 移植 | 不移植 |
|---|---|---|
| **pi-ai** | 消息/内容/工具/usage/stop reason/流式事件/Model/Faux provider；OpenAI-compatible + Anthropic | 42 家 provider 目录、OAuth、图片、classifier、Bedrock/Mistral/Vertex、CLI、telemetry wire |
| **pi-agent-core** | 全部 | — |
| **coding-agent 机制** | Session 树、Compaction、Skills、Extension 注册 | CLI/TUI、bash/文件/编辑工具、MCP/codemode、Durable/Env |

### 8.2 包名与文件映射

| 上游 | 我们 |
|---|---|
| `@earendil-works/pi-ai` | `PiUnityAgent.Ai` |
| `@earendil-works/pi-agent-core` | `PiUnityAgent.Core` |
| `pi-coding-agent` 中抽取的 Session/Compaction/Skills/Extensions/Resources | `PiUnityAgent.Runtime` |
| 宿主适配 | `PiUnityAgent.Hosts.Unity` / `PiUnityAgent.Hosts.Net8` |
| 可选能力包 | `PiUnityAgent.Ext.*` |

- C# 命名空间不能含连字符；程序集/命名空间统一 PascalCase。
- NuGet 包 ID 与程序集同名：`PiUnityAgent.Ai`、`PiUnityAgent.Core`、`PiUnityAgent.Runtime`。
- 文件名尽量保留上游 stem：`agent-loop.ts` → `AgentLoop.cs`；`stream-fn.ts` → `StreamFn.cs`；`types.ts` 拆到 `Types/` 并留 `_mapping.md`。
- 逐文件映射维护在 `PORTING.md`（待建）。

### 8.3 映射

| TS | C# |
|---|---|
| discriminated union | abstract record + pattern matching |
| `AbortSignal` | `CancellationToken` |
| `AsyncIterable<T>` | `IAsyncEnumerable<T>` |
| typebox schema | 轻量 JSON Schema 模型（或 NJsonSchema） |
| `convertToLlm` / `transformContext` | `Func<...>` / 接口 |
| `AgentMessage` declaration merging | `IAgentMessage` + 自定义实现 |
| 事件对象 | sealed record |
| `StreamFn` | 委托，返回 `IAsyncEnumerable<AssistantMessageEvent>` |

### 8.4 netstandard2.1 约束

- 可用：`IAsyncEnumerable`、`Span`、`Task`、`HttpClient`（Unity 侧用 UnityWebRequest）。
- 需要包：`System.Text.Json`（或改用 Newtonsoft）、`System.Threading.Channels`。
- 需要 polyfill：`IsExternalInit`、`RequiredMemberAttribute`、`CompilerFeatureRequiredAttribute`、`SetsRequiredMembersAttribute`。
- 禁止/替换：`System.Threading.Lock`、`Task.WhenEach`、`Base64Url`、`JsonSerializerOptions.IndentSize/NewLine`、`IReadOnlyList.Index()`、`ConfigureAwaitOptions`、`OperatingSystem.IsWindows`、`UnixFileMode`、`FileStreamOptions`、`ArgumentNullException.ThrowIfNull`、`Task.WaitAsync`、带 CancellationToken 的 `ReadAsStringAsync/ReadLineAsync` 等。
- 运行时：Unity Mono（不支持 IL2CPP 运行时注入）；前端 netstandard2.1、后端 net8.0。

## 九、质量约束

1. **可读优先**：命名表达意图，不用炫技写法；复杂处注释"为什么"，不注释"是什么"。
2. **可测优先**：Core 零 Unity/游戏引用；每个模块有单测；Faux provider 支撑无网测试。
3. **可解释优先**：讲不清的设计不写；写不出来讲解卡，说明还没想明白。
4. **不追求 1:1**：语义等价即可；C# 惯用法优先。
5. **不提前抽象**：先按模块落地，重复出现三次再抽公共件。
6. **不引入无关依赖**：每加一个包都要在决策日志说明理由。

## 十、节奏与讲解深度

- **流程分轨与模型路由**见 `docs/04-开发流程分轨与模型路由.md`：设计走重、移植走轻；强模型想，轻模型打。
- **批次节奏**：1–2 个模块为一批；每批结束做一次讲解 + 演示 + 复盘。
- **默认讲解深度**：关键决策 + 数据流 + 调优点（不逐行讲语法）。
- **"展开"**：用户说展开时，深入到源码级（原版 pi 文件/行号、C# 映射细节）。
- **"先做"**：用户说先做时，只保留决策点与风险，不展开教学。
- **复盘产出**：更新心智模型 + 调优手册 + 决策日志，而不是另开一堂课。

## 十一、反模式

1. 先看 Pi.NET 再看 pi（顺序反了）。
2. 把 Pi.NET 当行为标准，忽略它可能的偏离/缺陷。
3. 只读不跑：讲解卡没有对照验证。
4. 只跑不讲：代码能跑但说不出不变量和失败模式。
5. 讲解文档写成抄书/翻译，没有自己的理解。
6. 追求 1:1 移植，把 TS 的别扭结构搬进 C#。
7. 在 Core 里引用 Unity/GameData，破坏可测性。
8. 用 net9/net10 专有 API，导致 netstandard2.1 不可编。
9. 提前抽象：还没跑通就造"通用框架"。
10. 把"教学"变成额外负担，而不是交付物的一部分。

## 十二、里程碑与阶段边界

### M1 · PiUnityAgent.Ai + PiUnityAgent.Core

- **交付**：Faux provider；Agent loop；工具执行（串/并行、abort、steer/followUp）；流式事件；一个真实工具；Unity 示例挂载；单测。
- **不做**：Session 持久化、Compaction、Skills、扩展包加载（留给 2A）。
- **验收**：无网可跑；事件序列与 pi 对照语义一致；netstandard2.1 可编。

### 2A · PiUnityAgent.Runtime（agent 常用机制）

- **交付**：Session 树、Context 组装、Compaction、Extensions、Resources。
- **来源**：coding-agent 机制，不搬 CLI/TUI/编码工具。
- **验收**：长会话可用；分支/fork；压缩后可继续；扩展可注册工具/钩子。

### 2B · AI mod 常用功能（可选脚手架）

- **交付**：UI（F8/聊天/设置）、游戏钩子、记忆装配、诊断。
