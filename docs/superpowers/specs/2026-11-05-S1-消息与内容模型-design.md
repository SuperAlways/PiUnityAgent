> **状态**：spec v1，待用户 review。
> **阶段**：S1（pi-ai 消息与内容模型）。
> **参考版本**：pi（原版）`v1.5.0` / `f9a263655`；pi.net `main` / `2d6757b`。
> **当前实现**：草稿 tag `s1-draft-2026-11-05`，**不视为验收**；本 spec 通过后按 plan 返工。
> **目标**：底座形状尽量贴 pi（原版）与 pi.net，使 S2–S13 下游零适配；只有 Unity/netstandard2.1 硬约束才偏离，并记录代价。

## 一、范围

### 1.1 本阶段包含

`packages/ai/src/types.ts` 中与消息/内容/工具/上下文相关的类型：

- 消息：`SystemMessage`、`UserMessage`、`AssistantMessage`、`ToolResultMessage`、`Message`
- 内容块：`TextContent`、`ThinkingContent`、`ImageContent`、`ToolCall`、`ContentBlock`
- 计量：`Usage`、`StopReason`、`ThinkingLevel` / `ModelThinkingLevel`
- 工具：`Tool`、`ToolReference`、`ConstrainedSamplingConfig`、`GrammarFormat`、`GrammarVariants`
- 上下文：`Context`、`TranscriptContext`
- 可选类型：`ImagesContext` / `AssistantImages` / `ImagesStopReason`、`ClassifierContext` / `ClassifierQuestion` / `ClassifierAnswer` / `ClassifierResult`、`NestedToolCalls`、`DeferredHandle`、`AssistantMessageDiagnostic` / `DiagnosticErrorInfo`
- 运行时不变量：`MessageValidation`

### 1.2 本阶段不包含（属于 S2/S3，不是删除）

- `AssistantMessageEvent` 与事件流（S2）
- `Model` / `BaseModel` / provider / stream options（S3）
- 各 provider 的协议实现（S4/S5）
- OAuth、图片生成 API、分类 API 的**实现**（类型保留，实现后置）

### 1.3 A 方案原则

- 公共类型/字段/能力面完整；
- 未实现的 API 标 `TODO` / `NotSupportedException`，不删除类型；
- 本阶段只做类型与校验，不做 provider/网络/工具执行。

## 二、决策总表

| # | 决策 | pi（原版） | pi.net | Unity/2.1 约束 | 决定 | 偏离代价 |
|---|---|---|---|---|---|---|
| D1 | `string \| blocks` | 匿名联合 | `MessageContent` 包装类型 + 自定义 converter | STJ 8 可用 | **B：MessageContent 包装** | 多一层包装；构造需 `From` |
| D2 | `ContentBlock` 多态 | `type` 字段 | `JsonPolymorphic` / `JsonDerivedType` | 需验证 STJ 8 + netstandard2.1 | **A：优先特性；失败退自定义 converter** | 特性方式 AOT 有风险 |

## 四、C# 形状

### 4.1 MessageContent（D1）

```csharp
public abstract record MessageContent
{
    public sealed record Text(string Value) : MessageContent;
    public sealed record Blocks(IReadOnlyList<ContentBlock> Value) : MessageContent;

    public static MessageContent From(string text) => new Text(text);
    public static MessageContent From(IReadOnlyList<ContentBlock> blocks) => new Blocks(blocks);
    public IReadOnlyList<ContentBlock> ToBlocks();
}
```

- `SystemMessage.Content` / `UserMessage.Content` 使用 `MessageContent`；
- 自定义 `MessageContentJsonConverter`：string ↔ `Text`，array ↔ `Blocks`；
- null 处理：`SystemMessage` 的 content 缺失时写 `""`（对齐上游必填）。

### 4.2 Message 与角色（D5/D6）

```csharp
public abstract record Message
{
    public abstract string Role { get; }
    public required long Timestamp { get; init; }
}
```

- `Timestamp` 必填；
- 用 `required` + polyfill（netstandard2.1）在编译期强制；
- 四个派生 record 用 init 属性，不用 positional record；
- `Role` 为 wire 名（system/user/assistant/toolResult）。

### 4.3 ContentBlock 多态（D2）

```csharp
[JsonPolymorphic(TypeDiscriminatorPropertyName = "type")]
[JsonDerivedType(typeof(TextContent), "text")]
[JsonDerivedType(typeof(ThinkingContent), "thinking")]
[JsonDerivedType(typeof(ImageContent), "image")]
[JsonDerivedType(typeof(ToolCall), "toolCall")]
public abstract record ContentBlock;
```

- **S1 必须加一条验证测试**：`JsonSerializer.Serialize<ContentBlock>(new TextContent(...))` 输出 `"type":"text"`；
- 若 netstandard2.1 + STJ 8 不支持，退自定义 `ContentBlockJsonConverter`（wire 形状不变）。

### 4.4 枚举（D3）

- `StopReason`、`ThinkingLevel`、`ModelThinkingLevel`、`ImagesStopReason`、`ClassifierStopReason`、`NestedToolCallStatus` 全部自定义 converter；
- wire 值与 pi（原版）一致：`toolUse`、`xhigh`、`max` 等；
- 不使用 `JsonStringEnumMemberName`（.NET 9）。

### 4.5 ToolResultMessage（D4）

```csharp
public sealed record ToolResultMessage : Message
{
    public required string ToolCallId { get; init; }
    public required string ToolName { get; init; }
    public required IReadOnlyList<ContentBlock> Content { get; init; }
    public required bool IsError { get; init; }
    public object? Details { get; init; }
    public Usage? Usage { get; init; }
    public NestedToolCalls? NestedCalls { get; init; }
    public int? DurationMs { get; init; }
}
```

- `Details` 用 `object?`，与 pi.net 一致；
- 工具层负责保证 JSON 兼容；
- AOT/IL2CPP 风险记录在 §八。

### 4.6 必填字段（`required`）

| 类型 | 必填字段 |
|---|---|
| `Message` | `Timestamp` |
| `SystemMessage` | `Content` |
| `UserMessage` | `Content` |
| `AssistantMessage` | `Content`、`Api`、`Provider`、`Model`、`Usage`、`StopReason` |
| `ToolResultMessage` | `ToolCallId`、`ToolName`、`Content`、`IsError` |
| `Context` | `Messages` |
| `TranscriptContext` | `Messages` |
| `Tool` | `Name`、`Description`、`Parameters` |
| `ToolReference` | `Name` |

- `Usage` 的数值字段默认为 `0`，`Cost` 默认为空成本（不是 `required`）；
- 旧 JSON 缺失必填字段时，由 codec 补 `0` / `""` / 空数组，并记录诊断；
- `required` 需要 netstandard2.1 polyfill（`RequiredMemberAttribute` 等）。

### 4.7 ConstrainedSampling

上游是 `false | ConstrainedSamplingConfig`。C# 用包装类型保留两种状态：

```csharp
public abstract record ConstrainedSampling
{
    public sealed record Disabled : ConstrainedSampling;
    public sealed record Config(ConstrainedSamplingConfig Value) : ConstrainedSampling;
}

public abstract record ConstrainedSamplingConfig
{
    public sealed record JsonSchema(StrictMode Strict) : ConstrainedSamplingConfig;
    public sealed record Grammar(IReadOnlyDictionary<GrammarFormat, string> Variants) : ConstrainedSamplingConfig;
}
```

- `Tool.ConstrainedSampling` 类型为 `ConstrainedSampling?`；
- `false` → `Disabled`；对象 → `Config`；
- 下游不需要判断 `false`/对象混用。

## 五、序列化策略

| 类型 | 策略 |
|---|---|
| `MessageContent` | 自定义 converter（string vs array） |
| `ContentBlock` | `JsonPolymorphic`/`JsonDerivedType`（优先）；失败退自定义 converter |
| 枚举 | 自定义 converter |
| `object? Details` | STJ 运行时类型；工具层保证 JSON 兼容 |
| `JsonObject` / `JsonNode` | `System.Text.Json.Nodes` |
| 可空字段 | `JsonIgnore(Condition = WhenWritingNull)`，对齐上游 undefined 省略 |
| 属性命名 | camelCase（`JsonNamingPolicy.CamelCase`） |
| `Timestamp` | `long`（Unix ms） |

## 六、运行时不变量与校验

`MessageValidation` 保留：

1. `SystemMessage`：`Content` 的 blocks 只能含文本；
2. `UserMessage`：blocks 只能含文本/图片；
3. `AssistantMessage`：blocks 只能含文本/思考/工具调用；
4. `ToolResultMessage`：blocks 只能含文本/图片，`ToolCallId` 非空；
5. `ValidateToolPair(assistant, result)`：`ToolCallId` 必须对应 `ToolCall.Id`。

`MessageContent` 消除了“两个字段都设/都不设”的非法状态；校验只负责块类型与配对。

### 7.1 已有草稿测试（保留/改写）

- 消息构造与角色；

### 7.2 新增测试（spec 要求）

1. `MessageContent`：`From("text")` 序列化为字符串；`From(blocks)` 序列化为数组；null → `""`（SystemMessage）；
2. `ContentBlock` 多态：四种块 round-trip，`type` 正确；
3. 枚举：全部 wire 值 round-trip（`toolUse`、`xhigh`、`max` 等）；
4. `required`：缺少 Timestamp/必填字段时无法通过编译（用编译测试或说明）；
5. `object? Details`：JSON 兼容 details 正常序列化；
6. `JsonIgnore`：null 字段不出现在 JSON；
7. `MessageValidation` 的块类型/配对；
8. 可选类型：images/classifier/nested/deferred/diagnostics 构造通过。

### 7.3 验证 spike

- `JsonPolymorphic` + `JsonDerivedType` 在 `netstandard2.1` + `System.Text.Json 8.0.5` 下是否可用；
- 不通过则启用备选自定义 converter，spec 记录结果。

## 八、风险与开放问题

| 风险 | 影响 | 缓解 |
|---|---|---|
| `JsonPolymorphic` 在 2.1/STJ8 不可用 | ContentBlock 序列化失败 | 备选自定义 converter；wire 不变 |
| `object? Details` AOT/IL2CPP 反射 | 厂商内置场景风险 | 记录；必要时切 `JsonNode` |
| `required` 需要 polyfill | 编译问题 | 加 `RequiredMemberAttribute` 等 polyfill |
| 旧 JSON 缺 Timestamp/content | 反序列化失败 | codec 补 `0`/`""`，并记录诊断 |
| pi.net 命名偏离 | 下游对照困难 | 以 pi（原版）为准；`PORTING.md` 记录 |
