# 02 · Pi.NET 复用评估（2026-11-04）

> **状态**：实测报告 v1。基于 `pi-study/pi.net`（Pi.NET 1.4.5，对齐上游 pi v1.5.0）的本地构建实验。
> **结论先说**：**net8.0 可用（6 处小改，0 错误）；netstandard2.1 全量移植不划算（约 256 个错），应改用"后端用 Pi.NET + 前端薄客户端"或"裁剪版 Core"。**

---

## 一、Pi.NET 是什么

- 仓库：`https://github.com/AIDotNet/pi.net`（本地 `pi-study/pi.net`）
- 许可证：MIT
- 定位：pi 的 .NET 移植，**目标框架 `net9.0;net10.0`**，已发布 13 个 NuGet 包
- 规模：`Pi.Ai` 约 3.4 万行（10 种 API 实现、42 家 provider）、`Pi.Agent` 约 2,347 行
- 状态：版本 1.4.5，对齐上游 v1.5.0；P0–P3/P5 完成，TUI/Durable 部分进行中；测试量大（Pi.Ai.Tests 976、Pi.Agent.Tests 36）
- 特点：AI 驱动开发，语义对齐 TS 版；文档齐全（`docs/usage/01-pi-ai.md`、`02-pi-agent.md`）
- 与本项目的关系：**它几乎就是我们原计划要写的 Core**，但目标框架不兼容 Unity。

---

## 二、实测：重定向到 net8.0

测试对象：`Pi.Telemetry` + `Pi.Ai` + `Pi.Agent` 三个工程（Pi.Agent 依赖前两者）。

```bash
dotnet build src/Pi.Agent/Pi.Agent.csproj -p:TargetFrameworks=net8.0
```

### 2.1 初始错误

- **6 个**：`JsonStringEnumMemberNameAttribute`（.NET 9 新增，Pi.Telemetry 使用）

### 2.2 修补后

| # | 位置 | 问题 | 修法 |
|---|---|---|---|
| 1 | `Pi.Telemetry/TelemetrySchema.cs` | `JsonStringEnumMemberName`（.NET 9） | net8 下加同形 polyfill attribute |
| 2 | `Pi.Ai/Utils/Schema/SchemaResolver.cs` | `System.Threading.Lock`（.NET 9） | `object` |
| 3 | `Pi.Ai/Auth/OAuth/OpenAiCodexOAuth.cs` | `Base64Url`（.NET 9） | `Convert.FromBase64String` + URL 字符替换 |
| 4 | `Pi.Ai/Api/LlamaCppClassify.cs` | `JsonSerializerOptions.IndentSize/NewLine`（.NET 9） | 删除（仅格式化） |
| 5 | `Pi.Ai/Api/MistralConversations.cs` | `IReadOnlyList<T>.Index()`（.NET 9 LINQ） | `for` 循环 |
| 6 | `Pi.Agent/ToolExecution.cs` | `Task.WhenEach`（.NET 9） | `Task.WhenAny` + Remove 循环 |

结果：**0 error**（net8.0）。

### 2.3 语义注意

- `JsonStringEnumMemberName` 的 polyfill 只满足编译；System.Text.Json 8 的转换器**不会**按该 attribute 输出枚举 wire 名。若使用 `Pi.Telemetry` 的 wire 契约，需要自定义 converter 或去掉该特性。
- 其余 5 处为等价替换，行为一致。

## 三、实测：重定向到 netstandard2.1

在 net8 修补基础上，再加：

- `System.Text.Json` 8.0.5、`System.Threading.Channels` 8.0.0
- `IsExternalInit` / `RequiredMemberAttribute` / `CompilerFeatureRequiredAttribute` / `SetsRequiredMembersAttribute` / `JsonStringEnumMemberNameAttribute` polyfill
- `IReadOnlySet<string>` → `ISet<string>`
- `GeneratedRegex` → `static readonly Regex`
- `Stopwatch.GetElapsedTime` → `Elapsed`
- `ConfigureAwaitOptions` → `ConfigureAwait(false)`
- 非泛型 `TaskCompletionSource` → `TaskCompletionSource<bool>`

结果：**仍约 256 个错误**，类别包括：

| 类别 | 例子 |
|---|---|
| 文件/平台 API | `OperatingSystem.IsWindows`、`UnixFileMode`、`File.SetUnixFileMode`、`FileStreamOptions` |
| HTTP 重载 | `ReadAsStringAsync(CancellationToken)`、`ReadAsStreamAsync(CancellationToken)`、`ReadLineAsync(CancellationToken)` |
| Task/异步 | `Task.WaitAsync` |
| 参数校验 | `ArgumentNullException.ThrowIfNull` |
| Span/字符串 | `string.Create` 的 `Span<char>` 重载、`Uuid` 相关 |
| 正则 | `GeneratedRegex`（部分未替换完） |
| 其他 | `Stopwatch.GetElapsedTime` 等 |

**判断**：Pi.Ai 包含了大量与游戏 mod 无关的能力（OAuth 登录、CLI、Unix 文件权限、42 家 provider 目录、图片/分类、MCP/Chord 等），这些正是 netstandard2.1 错误的主要来源。**全量移植约需数周；裁剪版可行但需要重新界定 API 面。**

## 四、复用路线

### A. 后端引擎（推荐，先做）

**Pi.NET net8.0 + 太吾 .NET 8 后端进程。**

- 太吾后端实测为 .NET 8.0.22（`Backend/GameData.runtimeconfig.json`），可直接加载 net8 程序集；
- Agent 循环、LLM、会话、压缩、工具全部在后端；
- Unity 前端只做 UI + RPC 客户端 + 主线程工具；
- 需要 fork/vendor Pi.NET 并加 `net8.0` 目标（6 处补丁）。

**优点**：复用度最高、当天可跑通；**缺点**：只适用于有 .NET 后端的游戏（太吾可以，主流单进程 Unity 不行）。

### B. 裁剪版 netstandard2.1 Core（中期）

只移植：

- `Pi.Agent`（2.3k 行，几乎无平台依赖）
- `Pi.Ai` 的 **OpenAI-compatible + Anthropic** 两个 provider（砍掉 OAuth/CLI/图片/分类/其他 provider）
- 会话/压缩/技能（Pi.NET 的 `Pi.Durable` 里可借鉴，或自研）

**优点**：覆盖单进程 Unity；**缺点**：需要维护一个裁剪分支，且要补齐 `System.Text.Json`/polyfill/HTTP 重载等。

### C. 独立 .NET 10 sidecar（备选）

完整 Pi.NET 作为外部进程，Unity 通过本地 RPC 调用。

**优点**：零移植；**缺点**：玩家要装 .NET 10 运行时/多一个进程，不适合大众 Workshop 分发；适合开发期或高端用户。

## 五、建议的项目形态

```
PiAgent.Sdk            # 统一扩展契约（IExtension / Tool 声明 / 执行位）
PiAgent.Hosts.Unity    # Unity 前端：UI + RPC + 主线程工具
PiAgent.Hosts.Net8     # .NET 8 后端：引用 Pi.NET（net8 补丁版）
PiAgent.Core.NetStd    # 裁剪版 netstandard2.1（中期，供单进程游戏）
```

- **短期**：Hosts.Net8 直接用 Pi.NET；Hosts.Unity 只做薄客户端；说书人/药老先在后端跑 agent。
- **中期**：把 Pi.NET 的 Agent 语义抽成 `PiAgent.Sdk`，让裁剪版与 Pi.NET 版共享扩展契约。
- **长期**：若主流单进程 Unity 是重点，再投入 netstandard2.1 裁剪版。
