## 0. 背景

S1 定消息、S2 定流、S3 定 provider、S4/S5 接完四协议族后，模型“会说话”但不能做事。S6 补 pi `packages/agent` 的工具契约段：

- `AgentTool`：工具定义（模型字段 + UI 字段 + 运行时入口）；
- `parameters`：JSON Schema，一份两用（模型理解请求 + 运行时校验/强制转换）；
- `AgentToolResult`：三通道分流（模型 `content` / UI `details` / 程序化 `structuredContent`）；
- 错误编码：工具不存在、参数非法、execute 抛异常，统一成 `isError` 结果，模型有机会调整。

pi 的校验函数 `validateToolArguments` 在 `packages/ai`（`utils/validation.ts`），是 ai 包对 agent 包的支撑；`AgentTool` 等形状在 `packages/agent`。因此本阶段**同时落 `PiUnityAgent.Ai`（校验器）与 `PiUnityAgent.Core`（工具契约）**，与 `docs/06` 的 pi 包映射一致。

## 1. 目标 / 非目标

### 1.1 目标

- Core 新增工具契约公共形状：`AgentTool`、`AgentToolResult`、`AgentToolUpdateCallback`、`ToolExecutionMode`、`AgentToolReplay`；

## 3. 公共形状

### 3.1 `AgentTool`（Core）

对应 pi `AgentTool<TParameters, TDetails> extends Tool<TParameters>`；C# 无泛型参数，类型擦除为 `JsonNode?`（A）。

```csharp
namespace PiUnityAgent.Core.Tools;

public sealed record AgentTool
{
    public required string Name { get; init; }
    public required string Description { get; init; }

    /// <summary>JSON Schema 对象（模型声明 + 运行时校验共用）。对应 pi Tool.parameters。</summary>
    public required JsonObject Parameters { get; init; }

    /// <summary>UI 显示名（与只给模型的 Description 分受众）。对应 pi AgentTool.label。</summary>
    public required string Label { get; init; }

    /// <summary>provider 侧约束采样；对应 pi Tool.constrainedSampling（false 折叠为 null）。</summary>
    public ConstrainedSampling? ConstrainedSampling { get; init; }

    /// <summary>校验前的参数兼容垫片；入参为原始 JsonObject，返回待校验值。对应 pi prepareArguments。</summary>
    public Func<JsonObject, JsonNode?>? PrepareArguments { get; init; }

    /// <summary>structuredContent 的 JSON Schema（声明性）。对应 pi AgentTool.outputSchema。</summary>
    public JsonObject? OutputSchema { get; init; }

    /// <summary>执行入口。失败可抛异常，或返回 IsError=true 的结果；对应 pi AgentTool.execute。</summary>
    public required Func<string, JsonNode?, CancellationToken, AgentToolUpdateCallback?, Task<AgentToolResult>> Execute { get; init; }

    /// <summary>持久意图存在但结果未知时的恢复策略。对应 pi AgentTool.replay。</summary>
    public AgentToolReplay? Replay { get; init; }

    /// <summary>单工具执行模式覆盖；缺省走批次默认。对应 pi AgentTool.executionMode。</summary>
    public ToolExecutionMode? ExecutionMode { get; init; }

    /// <summary>模型可调用的声明视图（供 S9/transcript 使用）。对应 pi AgentTool extends Tool。</summary>
    public Tool Definition => new()
    {
        Name = Name,
        Description = Description,
        Parameters = Parameters,
        ConstrainedSampling = ConstrainedSampling,
    };
}
```

- `PrepareArguments` 入参从 pi 的 `unknown` 落为 `JsonObject`（`ToolCall.Arguments` 必为对象；畸形 JSON 由 `ArgumentsError` 在更早层表达），返回 `JsonNode?` 待校验（A/B）。
- `Execute` 的 `AbortSignal` → `CancellationToken`（A）；`onUpdate` 可空（A）。
- `Definition` 是自造便利属性（pi 用结构继承）→ D，收益=S9 无需二次拼装；代价=四字段重复，须在 S9 审计核对一致性。

### 3.2 `AgentToolResult` 与回调（Core）

```csharp
public sealed record AgentToolResult
{
    /// <summary>给模型的内容；pi 限制 Text|Image，我们用 ContentBlock 宽类型并在结果契约中约束。</summary>
    public IReadOnlyList<ContentBlock> Content { get; init; } = Array.Empty<ContentBlock>();

    /// <summary>给 UI/日志的结构化细节。对应 pi details。</summary>
    public JsonNode? Details { get; init; }

    /// <summary>给程序化调用方的机器可读结果。对应 pi structuredContent（不进模型）。</summary>
    public JsonNode? StructuredContent { get; init; }

    /// <summary>本次工具执行自身的 usage。对应 pi usage。</summary>
    public Usage? Usage { get; init; }

    /// <summary>失败标记：模型看到 content 为错误结果，details/structuredContent 仍保留。对应 pi isError。</summary>
    public bool IsError { get; init; }

    /// <summary>本批次提前终止提示（全批都为 true 才生效，归 S7）。对应 pi terminate。</summary>
    public bool Terminate { get; init; }

    /// <summary>pi createErrorToolResult 等价：文本错误 + details={} + isError。</summary>
    public static AgentToolResult FromError(string message, JsonNode? details = null)
        => new()
        {
            Content = new ContentBlock[] { new TextContent { Text = message } },
            Details = details ?? new JsonObject(),
            IsError = true,
        };
}

/// <summary>流式部分结果回调；execute() 结束后到达的调用由执行器忽略（S7）。对应 pi AgentToolUpdateCallback。</summary>
public delegate Task AgentToolUpdateCallback(AgentToolResult partialResult);

public enum ToolExecutionMode { Sequential, Parallel }

public enum AgentToolReplay { Never, Safe }
```

- `Details` 从 pi 泛型 `T` 落为 `JsonNode?`（A：C# 无泛型擦除后的 `any`）；`StructuredContent`/`Usage` 同。
- `Content` 用 `IReadOnlyList<ContentBlock>`（pi.net 同）而非 union 列表（A/B）；运行期契约=只能放 `TextContent`/`ImageContent`，由 S7 生成 `ToolResultMessage` 时按 S1 校验，S6 不额外加校验器（YAGNI）。
- `FromError` details 默认 `{}` 与 pi `createErrorToolResult` 一致；调用方可传结构化 details。
- `AgentToolReplay` / `ToolExecutionMode` 为枚举（A：TS 字符串联合）；S6 不序列化，wire 值留待持久化阶段（D16? 不登记，未序列化即无 wire 面）。

### 3.3 `ToolValidation`（Ai，公开面）

```csharp
namespace PiUnityAgent.Ai.Utils;

public static class ToolValidation
{
    /// <summary>按名找工具并校验参数（first match，pi Tool.find 同）；失败抛 InvalidOperationException。</summary>
    public static JsonNode? ValidateToolCall(IReadOnlyList<Tool> tools, ToolCall toolCall);

    /// <summary>校验并（必要时）强制转换参数；失败抛 InvalidOperationException，消息与 pi 逐字。</summary>
    public static JsonNode? ValidateToolArguments(Tool tool, ToolCall toolCall);
}
```

- 校验器内部形状 `ToolSchemaValidator`（Compile/Check/Coerce/Errors/Parse）与 Schema 辅助类全部 `internal`；不新增第三包或公开类型面。
- `ValidateToolCall` 消费的是 Ai `Tool` 列表；S7 的 `AgentTool` 列表经 `AgentTool.Definition` 投影后调用，或直接走 `ValidateToolArguments(tool.Definition, call)`。
- 每个 `Tool.parameters`（`JsonObject` 实例）编译一份，缓存用 `ConditionalWeakTable<JsonObject, ToolSchemaValidator>`（A：pi WeakMap 语义等价）。
- 错误类型 `InvalidOperationException`（B：pi 抛 `Error`，pi.net 用 InvalidOperationException）。

### 3.4 注册语义

- 注册单元 = `AgentTool`；容器/生命周期 = `AgentContext.Tools` / `AgentState.Tools`（S7 形状）与 S12 动态注册。
- S6 **不新增** `ToolRegistry`/`ToolCatalog` 自造类型（D/YAGNI）：pi 没有 registry，名字查找是 `find(name)` 首匹配；提前造容器只会与 S12 冲突。
- 重名策略 = 首匹配（pi 语义）；S7 执行时按此查找，S6 的 `ValidateToolCall` 同样首匹配。

## 4. 行为语义

### 4.1 参数校验管线（Ai）

按 pi `utils/validation.ts:33-120` 顺序：

1. `toolCall.ArgumentsError` 非空 → 抛 `Invalid arguments for tool "<name>": <argumentsError>`（不尝试执行/校验残缺参数，pi #10897）。
2. 深拷贝 `toolCall.Arguments`（`JsonNode.DeepClone()`），保证工具改自己的参数不污染 transcript。
3. `ToolSchemaValidator.Parse`：先 coercion 再 check：
   - 数值字符串→数字（含空白、空串→0，按 pi-schema）；
   - `"true"/"false"`→bool；
   - 单值→单元素数组、对象属性 coercions；
   - 可选属性 `null` 丢弃；
   - union 取首个可转换分支；
   - 空 `bytes`/字节串等按 pi-schema `coerce.ts` 完整语义。
4. 校验失败：按 `路径: 文案` 逐条列错误，JSON Pointer→点号路径（`/edits/0/oldText` → `edits.0.oldText`，空指针 → `root`），并附 `Received arguments:` 的缩进 JSON；整体文案与 pi 逐字：

```
Validation failed for tool "<name>":
  - <path>: <message>

Received arguments:
<arguments JSON, indented>
```

5. 成功返回 coerced 值（`JsonNode?`），永不修改输入。

### 4.2 执行契约与错误编码（Core 契约 + 注释，执行器归 S7）

S6 只定义并钉住契约，不实现 `runToolCall`：

- `Execute` 失败的两条合法路径：抛异常，或返回 `IsError = true` 的结果；**不要只把失败写在 content 里**。
- 工具不存在、参数校验失败、execute 抛异常 → S7 统一捕获并编码为 `isError: true` 的 toolResult（文本=`异常 message`；details 默认 `{}` 或错误结果自带 details）。
- `isError` 结果对模型是错误输入，对 UI/程序化调用方仍保留 `details`/`structuredContent`。
- `onUpdate` 在其 `execute()` 调用结束（成功或抛出）后到达的调用必须被忽略（S7 执行器实现；S6 契约注释钉住）。
- `Terminate` 是批次提前终止**提示**：只有最终化批次中**所有**结果都为 true 才触发（S7）。

### 4.3 三通道约束（文档级契约 + 测试）

| 通道 | 字段 | 约束 |
|---|---|---|
| 模型 | `Content` | 只放 `TextContent`/`ImageContent`；进历史永久占 token；必须自包含 |
| UI | `Details`、`Label`、`onUpdate` | 结构化、可事后重渲染；不承诺进模型 |
| 程序化 | `StructuredContent` | 机器可读；声明了 `OutputSchema` 的工具应总是给出 |

### 4.4 JSON Schema 校验器语义（Ai）

- 支持 pi-schema 的常用全量：`type`（string/number/integer/boolean/null/array/object）、`enum`/`const`、`properties`/`required`/`additionalProperties`、`items`/`prefixItems`、`contains`、`min/max` 系列、`pattern`、`format`（pi 21 种；本移植 19 种，缺 `hostname`/`idn-hostname`，登记 D21）、`allOf/anyOf/oneOf/not`、`$ref`/`$defs`、`dependentSchemas`、`propertyNames`、`patternProperties`；
- `unresolvedRefs: "reject"`：悬空 `$ref` 只在其位置拒绝，不整工具失效（pi 语义）；
- 已知不支持（移植 pi.net 现状，登记 D21）：`unevaluatedProperties`/`unevaluatedItems`、书签式 `$dynamicRef` 动态作用域、`hostname`/`idn-hostname` 两种 format；
- 这些关键字若出现在工具 schema 中，按“注解忽略/按可解析部分校验”，不得抛实现异常；
- 校验器只读 schema，不修改；schema 实例换新则重新编译（缓存键=实例）。

## 6. 三方偏离表（S6 收尾汇总；待独立审计核验）

| 项 | pi 原版 | pi.net | 我们 | 类别 | 原因 / 代价 |
|---|---|---|---|---|---|
| `AgentTool` 泛型 `TParameters/TDetails` | 泛型约束 schema/details | `ToolSchema` + `object?` | `JsonObject` + `JsonNode?` | A | C# 无泛型静态类型推导；运行时 schema 校验替代；代价=execute 参数无编译期类型 |
| `AgentTool extends Tool` | 结构继承 | 独立 record + `Definition` | 独立 record + `Definition` 属性 | B/D | `Ai.Tool` 为 sealed record 不能继承；四字段重复，S9 需核对投影一致 |
| `prepareArguments` 入参 `unknown` | unknown→params | `object?` | `JsonObject`→`JsonNode?` | A/B | toolCall.Arguments 必为对象；畸形 JSON 由 ArgumentsError 前置 |
| `execute` 的 `signal` | `AbortSignal?` | `CancellationToken` | `CancellationToken` | A | C# 惯用法 |
| `onUpdate` 返回 `void` | 同步 fire-and-forget | `Task` 回调 | `Task` 回调 | B | 便于异步事件 sink；“settle 后忽略”由 S7 执行器保证 |
| `replay` 字符串联合 | `"never"｜"safe"` | 未移植 | `AgentToolReplay?` 枚举 | A | C# 字符串联合→枚举；本轮不序列化 |
| `content` 限定 Text/Image | union 数组 | `ContentBlock` 列表 | `ContentBlock` 列表 | B/D | C# 无联合元素；运行期契约由 S7 生成消息时校验，S6 不加校验器 |
| `details`/`structuredContent` 类型 | `T` / `JsonValue` | `object?` | `JsonNode?` | A | STJ 统一 |

## 7. 风险与缓解

1. **Schema 移植精度**：pi-schema 语义细（coercion、错误文案、格式、draft 差异）。缓解=差分语料逐向量断言 + 覆盖守卫；任何不支持关键字登记 D21 而非静默吞。
2. **泛型擦除后的类型安全**：`Execute` 收到 `JsonNode?`，工具实现需自行按 schema 断言。缓解=文档钉契约 + S7 校验先行；代价可接受（pi.net 同）。
3. **四字段重复投影**：`AgentTool` 与 `Tool` 同名/同义字段漂移。缓解=`Definition` 单点投影 + S9 消费时测试锁定。
4. **S6/S7 边界回摆**：执行器放在 S7，S6 只定契约；若 S7 实现时发现缺形状，按“形状一次到位”原则回补 S6 spec 并审计，不得在 S7 私加。
5. **S1 ContentBlock 宽类型**：`AgentToolResult.Content` 允许 thinking/toolCall 值进入。缓解=S7 生成 `ToolResultMessage` 时按 S1 角色校验；S6 文档+示例钉住只放 text/image。
