# SOP 02 · 参考源同步与版本打钉（2026-11-05）

> **适用**：每个模块/批次开工前。
> **目的**：确保"原版 pi 第一、Pi.NET 第二"的参考顺序建立在最新且可复现的版本上。
> **原则**：同步一次、固定一个 tag、模块进行中不换版本；不追 main。

## 二、同步原版 pi

```bash
# 1. 同步标签（参考仓库若不继承代理，加 -c http.proxy=...）
git -C pi-study/pi fetch --tags --prune

# 2. 看最新 tag（按版本号倒序）
git -C pi-study/pi tag --sort=-v:refname | head -5

# 3. 看当前 HEAD
git -C pi-study/pi log -1 --date=short --format="%h %ad %s"

# 4. 若本地不是目标版本：检出目标 tag（或明确固定旧 tag）
git -C pi-study/pi checkout v1.5.0
```

记录：**tag / commit / 日期 / 上游相对本模块的状态（领先/落后）**。

## 三、同步 Pi.NET

```bash
git -C pi-study/pi.net fetch --tags --prune
git -C pi-study/pi.net describe --tags --abbrev=0
git -C pi-study/pi.net log -1 --date=short --format="%h %ad %s"
```

再读：

```bash
sed -n '1,60p' pi-study/pi.net/docs/migration-execution-status.md
```

记录：**版本 / commit / 日期 / 它对齐的上游版本**。

## 四、网络（GitHub 直连被阻断时）

参考仓库不一定继承本仓库的 `http.proxy`。两种写法：

```bash
# 方式 A：命令内指定
git -c http.proxy=http://127.0.0.1:7897 -C pi-study/pi fetch --tags

# 方式 B：给参考仓库单独配置（长期）
git -C pi-study/pi config http.proxy http://127.0.0.1:7897
```

诊断方法见 `sop/01-GitHub推送与代理配置-2026-11-05.md`。

## 五、写版本卡

同步结果写入两处：

1. 本模块讲解卡 §0"版本与同步"；
2. `PORTING.md` §0 版本卡。

格式：

```text
同步日期：2026-11-05
原版 pi：v1.5.0 / <commit> / 2026-11-02；相对本模块：领先
Pi.NET：main 2d6757b / 2026-11-05；对应上游：v1.5.0
备注：<是否有未跟的提交/本地改动>
```

## 六、纪律

1. **每模块/批次同步一次**，不是每敲一段代码同步一次。
2. **模块进行中不换版本**；发现上游漂移先记录，不打断当前模块。
3. **只对齐明确 tag**，不追 `main`。
4. 同步后先看 `git diff <旧tag>..<新tag> -- packages/ai packages/agent`（以及 2A 的 `coding-agent/src/core`），把变化写进讲解卡"上游增量"。
5. 同步结果不确定时，固定旧 tag，不边写边换。
