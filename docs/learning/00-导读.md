# 00 · 导读：怎么读这个移植

> **一句话**：这个项目不是"把 pi 翻译成 C#"，而是"用最新原版 pi 做行为基准，用 Pi.NET 做语言映射参考，重做一个 Unity 可用的 netstandard2.1 底座"。

## 一、先建立三个坐标

| 坐标 | 是什么 | 读它的时候问什么 |
|---|---|---|
| **原版 pi** | TypeScript，行为真相源 | 它做什么？为什么？边界在哪？失败了会怎样？ |
| **Pi.NET** | 社区 .NET 9/10 移植，语言参考 | 这个 TS 特性在 C# 里怎么写？它踩过什么坑？ |
| **PiUnityAgent** | 我们的 netstandard2.1 重构 | 语义是否等价？Unity 能不能跑？能不能单测？ |

顺序永远是：**原版 → Pi.NET → 我们**。反了就会把别人的实现当成行为标准。

## 二、推荐阅读顺序

1. 本导读
2. `docs/00-项目定位与边界.md`：这个底座为谁、不做什么
3. `docs/03-开发方法-拆解学习与移植约定.md`：开发循环与交付物
4. `PORTING.md`：上游文件 → 我们的文件
5. 按 M1 模块读教学篇（01→02→03…），每篇配代码与单测

## 三、每个模块怎么学

读一篇教学文档时，先回答三个问题：

1. **它解决什么问题？** 如果没有它，agent 会在哪里坏？
2. **它的不变量是什么？** 哪些顺序/状态不能乱？
3. **它的旋钮在哪？** 出问题时，先调什么？

回答不出来，说明还没懂；回到原版 pi 的源码，不要先看我们的实现。

## 四、代码与文档的对应

- 每个模块 = 代码 + 单测 + 讲解卡 + 教学篇 + 版本卡。
- 讲解卡是"开工前的一页纸"，教学篇是"做完后的沉淀"。
- 两者都留在仓库里；聊天记录不算交付物。

## 五、给后来者

如果你是第一次读这个项目：

- 不要从 `AgentLoop.cs` 开始硬读；先读 `docs/learning/01`，知道一条消息怎么走完一圈。
- 不要先看 Pi.NET；它对语言映射很有用，但行为可能偏离上游。
- 遇到"为什么不用现成的 Pi.NET"：读 `Q&A.md` 第 1 条。
