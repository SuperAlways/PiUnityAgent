> **状态**：v1（2026-11-07），用户已拍板「端口归属 B」。
> **定位**：PiUnityAgent 与 UnityLlmTransport 的**唯一正式接缝**。本文只定义两侧的端口、映射与责任边界；不重复任何一方的内部实现细节。
> **权威分工**：

## 一、决策

**B：PiUnityAgent.Ai 自己拥有传输端口；UnityLlmTransport 是端口的一个实现/适配方，不是 Ai 的依赖。**

```
PiUnityAgent.Ai（provider 协议；netstandard2.1；零 UnityEngine）
        │  只依赖 PiUnityAgent 自有的 Fetch 端口
        ▼
PiUnityAgent.Hosts.Unity / Ext（Unity 胶质层；可引用 UnityEngine）
        │  适配器：Fetch 端口 ↔ IStreamingHttpTransport
        ▼
UnityLlmTransport.Abstractions（共享通讯契约；零 UnityEngine）
        ▲
        │  具体实现
UnityLlmTransport.UnityWebRequest（UWR，Phase 2 已实机验证）
UnityLlmTransport.HttpClient（Phase 3，桌面/.NET）
（未来）其他通讯组件 / 自写 transport
```

依赖方向：

- `PiUnityAgent.Ai` → **只依赖自己**的 `FetchFunction`/`FetchRequest`/`IFetchResponse`；
- `PiUnityAgent.Hosts.Unity` / `PiUnityAgent.Ext.*` → 适配器；可引用 `UnityLlmTransport.Abstractions` 与具体实现；
- `UnityLlmTransport.*` → 不引用 PiUnityAgent 的任何类型；
- **`PiUnityAgent.Ai` 不引用 `UnityLlmTransport`、`UnityEngine`、`GameData`、`Harmony`。**

选 B 的理由、A 方案对比与代价见决策记录。

## 二、Fetch 端口形状（PiUnityAgent 自有）

> 这是 pi 原版 `fetch?: FetchFunction` 的 C# 等价物；形状以 pi 为准，C# 表达借鉴 pi.net 与 UnityLlmTransport。
> 文件落点：`src/PiUnityAgent.Ai/Types/Fetch.cs`（S3 返工 v2）。

```csharp
namespace PiUnityAgent.Ai.Types;

/// <summary>pi `fetch` 的 C# 等价物；由宿主注入。</summary>
public delegate Task<IFetchResponse> FetchFunction(
    FetchRequest request,
    FetchOptions? options,
    CancellationToken cancellationToken);

public sealed record FetchRequest(
    string Method,
    string Url,
    FetchHeaders Headers,
    ReadOnlyMemory<byte> Body)
{
    /// <summary>大请求（图片/多模态）用工厂重建流；设置后忽略 Body。必须可重放。</summary>
    public Func<CancellationToken, Task<Stream>>? BodyFactory { get; init; }
}

/// <summary>Headers：名称大小写不敏感；请求中 value=null 表示“抑制默认头”。</summary>
public sealed class FetchHeaders : Dictionary<string, string?>
{
    public FetchHeaders() : base(StringComparer.OrdinalIgnoreCase) { }
    public FetchHeaders(IDictionary<string, string?> values)
        : base(values, StringComparer.OrdinalIgnoreCase) { }
}

public sealed record FetchOptions
{
    public TransportKind? Kind { get; init; }
    public TimeSpan? ConnectTimeout { get; init; }
    public TimeSpan? FirstByteTimeout { get; init; }
    public TimeSpan? IdleTimeout { get; init; }
    public int? MaxResponseBytes { get; init; }
    public IReadOnlyDictionary<string, string>? Env { get; init; }
    public string? SessionId { get; init; }
}

public interface IFetchResponse : IAsyncDisposable
{
    int StatusCode { get; }
    FetchHeaders Headers { get; }

    /// <summary>响应体；任意状态码都可读（错误体也是 Body）。</summary>
    Stream Body { get; }

    /// <summary>立即中止底层连接；幂等。</summary>
    void Abort();
}

public enum FetchErrorKind
{
    Connect,
    Tls,
    Proxy,
    Protocol,
    FirstByteTimeout,
    IdleTimeout,
    Cancelled,
    Aborted,
    Overflow,
    Unsupported
}

public sealed class FetchException : Exception
{
    public FetchErrorKind Kind { get; }
    public int? StatusCode { get; init; }
    public FetchHeaders? Headers { get; init; }
    public string? ErrorBody { get; init; }
    public bool IsRetryable { get; init; }
}
```

`TransportKind` 沿用 pi 的联合（wire 值一致）：

```csharp
public enum TransportKind { Auto, Sse, WebSocket, WebSocketCached }
```

### 端口行为约定

1. **响应头之前失败** → 抛 `FetchException`（连接/TLS/代理/首字节超时/取消等）；**一旦拿到 HTTP 状态（包括 4xx/5xx）** → 返回 `IFetchResponse`，由 provider 决定读错误体还是抛协议错误。
2. **取消**：`CancellationToken` 必须桥接到底层连接中止；取消后 `Body.ReadAsync` 尽快结束（完成或异常）。`Abort()` 是显式中止，幂等。
3. **`Body` 是 `Stream`**：流式响应为增量流；非流式可读完。`DisposeAsync` 释放会话；未读完时实现应中止或排空，避免连接泄漏。
4. **传输只吐字节**：不判断 `[DONE]`、不拼 JSON、不聚合 `tool_calls`/`usage`/`stopReason`。
5. **端口零 UnityEngine、零版本判断**；平台/版本差异全部留在适配器与实现层。
6. **默认解析**：`StreamOptions.Fetch == null` 时优先用 **provider 构造时注入的默认 `FetchFunction`**（S4 provider ctor / `StaticProvider` 闭包）；`Models` 不持有全局 fetch、不使用静态单例。provider 也没有默认 → 以终态 `Error` 编码（不抛），文案明确“未配置通讯层”。
7. **不暴露能力位**：provider 不判断平台/Unity 版本；需要 WebSocket 时用独立的 WebSocket 端口（S5+），不要往 Fetch 端口塞传输能力枚举。

## 三、适配器契约（Host 侧）

### 3.1 Unity：`UnityLlmTransportFetch`

位置：`PiUnityAgent.Hosts.Unity`（或独立 `PiUnityAgent.Ext.Transport.UnityLlmTransport`，按多传输策略定）。

```csharp
public sealed class UnityLlmTransportFetch
{
    public UnityLlmTransportFetch(
        IStreamingHttpTransport transport,
        TransportOptions baseline); // 代理/TLS/默认超时由宿主装配

    public Task<IFetchResponse> FetchAsync(
        FetchRequest request,
        FetchOptions? options,
        CancellationToken cancellationToken);
}
```

映射：

| Fetch 端口 | UnityLlmTransport |
|---|---|
| `FetchRequest.Method/Url/Headers/Body/BodyFactory` | `TransportRequest` |
| `FetchOptions.Kind` | `TransportOptions.Kind`（`TransportKind` 同名同值） |
| `FetchOptions.Connect/FirstByte/IdleTimeout` | `TransportOptions.*` |
| `FetchOptions.MaxResponseBytes` | `TransportOptions.MaxResponseBytes` |
| `FetchOptions.Env` | `TransportOptions.Env`（代理变量等） |
| `FetchOptions.SessionId` | `TransportOptions.SessionId` |
| `FetchFunction` 的 `CancellationToken` | `IStreamingHttpTransport.OpenAsync(ct)`；适配器同时监听取消并 `session.Abort()` |
| `IFetchResponse.Abort()` | `ITransportSession.Abort()` |
| `IFetchResponse.StatusCode/Headers/Body/DisposeAsync` | `ITransportSession.*` |
| `TransportException` | `FetchException`（`TransportErrorKind` → `FetchErrorKind`） |

代理/TLS/客户端证书等**不进入 Fetch 端口**；由宿主构造 `TransportOptions` 时装配。provider 不感知。

### 3.2 .NET 8：`HttpClientFetch`

位置：`PiUnityAgent.Hosts.Net8`（S13/2B 可选）。

- `HttpClient.SendAsync(request, HttpCompletionOption.ResponseHeadersRead, ct)`；
- 状态/headers/`ReadAsStreamAsync` → `IFetchResponse`；
- `FetchOptions` 超时映射为 per-call `CancellationTokenSource`；
- 异常按 `FetchErrorKind` 分类；
- 代理/TLS 由注入的 `HttpClientHandler` 配置。

### 3.3 测试：`MockFetch`

- 脚本化字节块/延迟/错误/取消/超时；
- 供 S3/S4/S5 单测使用，CI 无网、无 key；
- 不依赖 Unity 或 UnityLlmTransport。

### 3.4 其他通讯组件

任何实现只要满足以下之一即可接入：

1. 实现 `IStreamingHttpTransport`，复用上述适配器；
2. 直接实现 `FetchFunction`（最薄路径）；
3. 在 Host 层写一个自己的适配器。

## 四、选项与协议映射（S3 定字段，S4 定行为）

| pi / `StreamOptions` | Fetch 端口 / provider 责任 | 归属 |
|---|---|---|
| `signal` / `CancellationToken` | `FetchFunction` 的 ct + `IFetchResponse.Abort()` | 端口 |
| `headers` | `FetchRequest.Headers`（`null` 抑制默认头） | 端口 |
| `fetch` | `FetchFunction? Fetch` | **S3 形状** |
| `timeoutMs` | `FetchOptions.Connect/FirstByte/IdleTimeout` | S4 映射 |
| `maxRetries` / `maxRetryDelayMs` | provider 级重试包装（首字节前）；流开始后不重试 | S4 |
| `onPayload` | provider 发送前改写 body | S4 |
| `onResponse` | provider 收到响应后回调（`ProviderResponse`） | S4 |
| `onProviderStreamEvent` | provider 在解析前观察原始字节 | S4 |
| `env` | `FetchOptions.Env` | 端口/S4 |
| `identity` | 请求 headers（UA 等） | S4 |
| `cacheRetention` / `sessionId` | provider headers / `FetchOptions.SessionId` | S4 |
| `transport` | `StreamOptions.Transport` → `FetchOptions.Kind` | S3 形状 / S4 映射 |
| `websocketConnectTimeoutMs` | 独立 WebSocket 端口（后置） | S5+ |
| `telemetry` | provider/host observer（不进入端口） | 后续 |
| `deferred` | 同一 Fetch 端口，再次请求/取消 | S8 |
| 图片 / 分类 | 同一 Fetch 端口，JSON/二进制 | 2B/后续 |
| API Key / OAuth | provider/认证模块注入 headers；端口只携带 headers | S4/S5 |
| 代理 / TLS | 宿主装配 `TransportOptions` | Host |
| 版本 / 平台能力 | 不进入 Ai；实现层归一化 | Host |

**SSE 解析**：Fetch 端口只返回 `Stream`；`[DONE]`、`data:` 行协议、JSON 聚合、`tool_calls`/`usage`/`stopReason` 全部在 `PiUnityAgent.Ai`（S4/S5）。SSE 解析器可以复用 `UnityLlmTransport.Sse`、vendor `System.Net.ServerSentEvents`，或仿 pi.net `AiSse` 自写；**这是 S4 的实现选择，不改变端口形状。**

## 五、版本锁与实机证据

- 锁：`UnityLlmTransport` commit `87db637`（Phase 2 终审，2026-11-07）。
- Phase 2 结果：`UnityLlmTransport/docs/spike/phase2-results.md`。
- **矩阵**：Unity `2021.3.45f1c2` / `6000.3.28f1` / `6000.6.8f1` × Mono/IL2CPP = 6 组，每组 15/15 `|OK|`。
- 关键事实：
  - UWR 真流式、取消=`Abort`、首字节/空闲超时、溢出、500 错误体、TLS、重定向、Abort 后读侧干净，均通过；
  - UWR 自动解压 gzip 但响应头仍标 `Content-Encoding: gzip`；适配层用 magic 嗅探，`Compression` 能力保留；
  - 显式代理在 UWR 下 `Unsupported`；系统代理可用；
  - `ConnectTimeout` 在 UWR 下实际约束到响应结束（实现偏离，已在 Phase 2 spec 记录）；
  - U11 只证明读侧干净；引擎层 `ReceiveData` 残留计数直证推迟 Phase 3。
- **2022.3 测试主基线已补测通过**：Hub 编辑器 `2022.3.62f3c1`（Mono/IL2CPP U1–U11 15/15，2026-11-07）；太吾游戏实际 `2022.3.62f2`（f3c1/f2 不可混写，最终游戏内验收以 f2 为准）。Phase 2 现覆盖 2021.3/6.3/6.6 + 2022.3.62f3c1；**不阻塞 S3**。

## 六、测试与验收

1. **端口单测**：`MockFetch` 覆盖流式、错误体、取消、首字节/空闲超时、错误分类、`Abort` 幂等。

4. **S13 实机**：UWR 适配器 + PiUnityAgent provider，三版本 Mono；IL2CPP 冒烟；2022.3 补测。
5. **门禁**：`PiUnityAgent.Ai` 零 UnityEngine / 零 UnityLlmTransport 引用；`netstandard2.1` 编译 0 错误；Release 0/0。
