# 第一部分 · 开工前：概念与决策

## 1. 它解决什么问题

模型只认四种角色：`system`、`user`、`assistant`、`toolResult`。
但 agent 还要表达：文本、思考、图片、工具调用、工具结果、用量、停止原因、错误。

**消息与内容模型就是这层共同语言**：

- provider 用它发送/解析；
- agent loop 用它读懂"模型要调哪个工具"；
- 会话/压缩/日志用它序列化。

没有它，每个 provider、每个工具、每个会话格式都会各造一套。

## 2. 一条消息的旅程

```
SystemMessage（prompt + 工具声明）
        │
        ▼
UserMessage（文本 / 文本+图片）
        │
        ▼
AssistantMessage（文本 / 思考 / 工具调用 + usage + stopReason）
        │
        ├─ 没有 ToolCall → 本轮结束
        └─ 有 ToolCall
                ▼
        ToolResultMessage（toolCallId + content + isError）
                │
                ▼
        下一轮 AssistantMessage
```

`Context`（调用方输入，可简写 `systemPrompt` / `tools`）与 `TranscriptContext`（规范化后，prompt/工具声明折进 system message）要分开。

## 3. 三条关键不变量

1. **角色与内容块匹配**
   - system：文本；
   - user：文本/图片；
   - assistant：文本/思考/工具调用；
   - toolResult：文本/图片，且必须有 `toolCallId`、`toolName`、`isError`。

2. **工具结果必须能追溯到工具调用**
   - `ToolResultMessage.ToolCallId` 必须对应某个 `ToolCall.Id`；
   - 不允许出现没有调用方的工具结果。

3. **失败是数据，不是异常**
   - 模型/网络失败：`StopReason.Error` / `Aborted` + `ErrorMessage`；
   - 工具失败：`IsError = true`；
   - 参数 JSON 坏：`ArgumentsError` 有值，`Arguments = {}`；
   - 截断：`StopReason.Length`；
   - 推理被过滤：`ThinkingContent.Redacted = true`，签名保留。

### 3.1 六张契约卡（复习用）

> 只记"必须成立的事"；字段名、默认值、wire 值属于按需查阅层。

**卡 1 · 角色 × 内容块矩阵**
- 必须成立：system 只文本；user/toolResult 文本+图片；assistant 文本+思考+工具调用。
- 在哪强制：`MessageValidation.Validate`（**opt-in**，不是自动）。
- 破坏后果：provider 序列化失败，或内容块被静默丢弃。
- 验收问法：user 消息里塞一个 `ThinkingContent`，谁会拦住？

**卡 2 · 工具调用 ↔ 结果按 id 配对**
- 必须成立：`ToolCallId` 非空，且必须命中某条 assistant 的 `ToolCall.Id`；**与顺序无关**。
- 在哪强制：`MessageValidation.ValidateToolPair`（opt-in，S7 必须调）。
- 破坏后果：结果挂错调用，或出现无调用方的孤儿结果。
- 验收问法：工具并行执行、结果顺序颠倒，配对还成立吗？

**卡 3 · 失败是数据**
- 必须成立：响应失败/中止、工具失败、参数损坏、输出截断全部编码在消息里，不向调用方抛异常。
- 在哪强制：字段形状（S1）+ 事件终态约束（S2）+ provider adapter 写入（S4/S5）+ 工具层写入（S7）。
- 破坏后果：agent loop 被异常打断，无法决定下一步。
- 验收问法：网络断了，调用方收到的是异常还是终态消息？

**卡 4 · 两态内容**
- 必须成立：`MessageContent` 只能是 `Text` 或 `Blocks`；string 进模型前由 `ToBlocks()` 变成 `TextContent` 块。
- 在哪强制：类型系统 + `MessageContentJsonConverter`。
- 破坏后果："两个字段都设/都不设"的非法状态；provider 收到空内容。
- 验收问法：`SystemMessage.Content = "hi"` 和 `Blocks([Text("hi")])` 对 provider 是否等价？

**卡 5 · 上下文只能经规范化进入 provider**
- 必须成立：`Context`（SystemPrompt/Messages/Tools）→ `TranscriptContext`（已折进 SystemMessage）；只有 normalizer 能产出后者。
- 在哪强制：目前**只有注释，未实现、未强制**（S9）。
- 破坏后果：system prompt 或工具声明丢失/重复，provider 看到的上下文与宿主意图不一致。
- 验收问法：把原始 `Context` 直接交给 provider，会丢什么？

**卡 6 · 线格式与不可变**
- 必须成立：role wire 名 `system/user/assistant/toolResult`；块判别符 `type`；枚举值 `toolUse/xhigh/max`；时间戳 Unix ms；除 `AssistantMessage.DurationMs` 外全部 `init`。
- 在哪强制：属性/converter + `required` + 类型系统。
- 破坏后果：S10 存盘读不回、S2 无法写耗时、下游随意改消息。
- 验收问法：为什么 `DurationMs` 是唯一可写字段？

## 4. 失败四态：形式、产生、消费

> 四种真正的失败。`Redacted` 是安全变形，不是失败，单列在后面。

| 状态 | 形式 | 谁产生 | 谁消费 | 是否重试 |
|---|---|---|---|---|
| **响应失败** | `StopReason.Error` + `ErrorMessage` | provider adapter（HTTP/网络/解析失败，S4/S5）；S3 `Models` 兜底 | S2 终态 `error` 事件；S7 立即结束本轮 | 不自动重试 |
| **响应中止** | `StopReason.Aborted` + `ErrorMessage` | 取消令牌（v2 起 `StreamOptions.CancellationToken`；provider 内层流产 Aborted） | 同上；保留已生成内容 | 不重试 |
| **工具失败** | `ToolResultMessage.IsError = true` + 可读错误内容 | S7 准备/执行工具（未找到、校验失败、抛异常、被拦截） | 作为 toolResult 回填上下文；下一轮模型看到 | 由模型决定 |
| **参数损坏** | `ToolCall.ArgumentsError` + `Arguments = {}` | provider 在 toolcall 结束时解析参数失败 | S7 校验失败 → 不执行工具，转成 `IsError` 结果 | 由模型重发 |
| **输出截断** | `StopReason.Length` | provider 的 finish_reason（max_tokens/length） | S7 拒绝执行该消息里的工具调用，全部转成 `IsError` 结果 | 模型收错误后可重发 |

补充：

- `RawStopReason` 只做诊断，不要拿它分支；对外语义看 `StopReason`。
- `Redacted` 不是失败：`ThinkingContent.Redacted = true`，签名保存加密载荷，回放时原样送回。
- S2 终态约束：`Done` 只能是 stop/length/toolUse/deferred；`Error` 只能是 error/aborted（`AssistantMessageEventValidation`）。
- `MessageValidation` 目前是 opt-in：S7 必须在工具结果回填、provider 入口主动调用。

## 5. 可调旋钮

| 旋钮 | 影响 | 备注 |
|---|---|---|
| `maxTokens` | 单次输出上限 | `Model.maxTokens` / 请求选项 |
| `thinkingLevel` | 推理预算 | `off`…`max`；provider 可能不支持 |
| `samplingParams` | 温度/采样 | 模型默认 + 请求覆盖 |
| `toolChoice` | 是否允许/强制工具 | `auto` / `none` |
| `stopReason` 处理 | 是否重试/压缩 | 由 agent loop 决定 |

## 6. TS → C# 映射

| TS | C# |
|---|---|
| `Message` 联合 | `abstract record Message` + 四个派生 record |
| `ContentBlock` 联合 | `abstract record ContentBlock` + 四个派生 record |
| `content: string \| blocks` | `required MessageContent`（`Text`/`Blocks` 联合）+ `MessageValidation` |
| `JsonObject` | `System.Text.Json.Nodes.JsonObject` |
| `number`（时间戳） | `long`（Unix ms） |
| `ToolResultMessage<T>` 条件类型 | 非泛型 + `object? Details` |
| 字符串字面量联合 | `enum` + 自定义 `JsonConverter`（wire 往返） |
| 可选字段 `?` | `T?` / nullable；必填字段用 `required`（polyfill） |

命名规则：类型名与上游一致；C# 只做 PascalCase、`Async` 后缀、`I` 前缀、union→record 的机械变换。

# 第二部分 · 实现后：代码、测试与差异

## 10. C# 设计取舍

| 决策 | 选择 | 理由 |
|---|---|---|
| union 类型 | 抽象 record + 派生 | C# 没有 discriminated union |
| `string \| blocks` | `MessageContent` 联合（`Text`/`Blocks`）+ 自定义 `JsonConverter` | 读/写按 JSON 实际形状（string vs array）分派；null 归一为空 blocks |
| `ContentBlock` 多态 | `[JsonPolymorphic]`（判别符 `type`）+ `[JsonIgnore] Type` | wire 靠 `type` 判别；C# 侧 `Type` 属性只作便利读取，参与 JSON 会与判别符冲突 |
| 必填字段 | `required` + `RequiredMemberAttribute` polyfill | 构造期强制，不再靠运行时校验兜底 |
| `ToolResultMessage<T>` | 非泛型 + `object? Details` | 避免泛型污染；Details 不预设 JSON 形状 |
| `StopReason` / `ThinkingLevel` | enum + 自定义 `JsonConverter` | wire 与 pi 一致；未知 wire 值抛错而非静默 |
| `init` / record | `IsExternalInit` + `RequiredMembers` polyfill | netstandard2.1 没有这些类型 |
| `JsonObject` | `System.Text.Json.Nodes` | 与 provider JSON 参数对应 |

## 13. 与上游 / Pi.NET 的差异

- **上游**：类型名一致；
- **我们**：`string | blocks` 折成 `MessageContent` 联合；必填字段用 `required`；`ContentBlock.Type` 加 `[JsonIgnore]`（wire 用 `type` 判别符）；`ToolResultMessage` 非泛型 + `object? Details`；`StopReason`/`ThinkingLevel` 用自定义 enum converter；图片输入/输出用 marker interface；
- **Pi.NET**：只参考 C# 写法，不照抄字段；冲突以上游为准。
