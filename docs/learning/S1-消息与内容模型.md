## 一、这一层到底在解决什么

模型只认四种角色：`system`、`user`、`assistant`、`toolResult`。
但 agent 还要表达：文本、思考、图片、工具调用、工具结果、用量、停止原因、错误。

**消息与内容模型就是这层共同语言**：

- provider 用它发送/解析；
- agent loop 用它读懂"模型要调哪个工具"；
- 会话/压缩/日志用它序列化。

没有它，每个 provider、每个工具、每个会话格式都会各造一套。

## 二、一条消息的旅程

```
SystemMessage（prompt + 工具声明）
        │
        ▼
UserMessage（文本 / 文本+图片）
        │
        ▼
AssistantMessage（文本 / 思考 / 工具调用 + usage + stopReason）
        │
        ├─ 没有 ToolCall → 本轮结束
        └─ 有 ToolCall
                ▼
        ToolResultMessage（toolCallId + content + isError）
                │
                ▼
        下一轮 AssistantMessage
```

C# 里 `Message` 是抽象 record，四种消息各自派生；`ContentBlock` 也是抽象 record，`TextContent` / `ThinkingContent` / `ImageContent` / `ToolCall` 派生。

---

## 三、三个不变量，在代码里怎么落

### 1. 角色与内容块匹配

- `SystemMessage`：`Content` 或 `ContentBlocks` 二选一，块只能是文本；
- `UserMessage`：`Content` 或 `ContentBlocks` 二选一，块只能是文本/图片；
- `AssistantMessage`：块只能是文本/思考/工具调用；
- `ToolResultMessage`：块只能是文本/图片。

C# 的类型系统表达不了"二选一"和"只允许某些块"，所以用 `MessageValidation.Validate` 在边界处校验。

### 2. 工具结果必须能追溯到工具调用

`ToolResultMessage.ToolCallId` 必须对应某个 `ToolCall.Id`。
`MessageValidation.ValidateToolPair(assistant, result)` 负责配对检查。

### 3. 失败是数据，不是异常

- 模型/网络失败：`StopReason.Error` / `Aborted` + `ErrorMessage`；
- 工具失败：`IsError = true`；
- 参数 JSON 坏：`ToolCall.ArgumentsError` 有值，`Arguments = {}`；
- 截断：`StopReason.Length`；
- 推理被过滤：`ThinkingContent.Redacted = true`，签名保留。

## 四、C# 设计取舍（重点）

| 决策 | 选择 | 理由 |
|---|---|---|
| union 类型 | 抽象 record + 派生 | C# 没有 discriminated union；pattern matching 可读 |
| `string \| blocks` | 两个可空字段 + 校验 | 构造简单；类型系统不强制，靠边界校验 |
| `ToolResultMessage<T>` | 非泛型 + `JsonNode? Details` | 避免泛型污染；需要强类型时在工具层反序列化 |
| `StopReason` | enum + `ToWire/FromWire` | 类型安全；wire 值与 pi 一致 |
| `init` / record | `IsExternalInit` polyfill | netstandard2.1 没有该类型 |
| `JsonObject` | `System.Text.Json.Nodes` | 与 provider 的 JSON 参数直接对应 |

> 这些取舍都写进了 `Types/_mapping.md`；以后若真实调用点觉得别扭，再调整，不提前抽象。

## 七、与上游 / Pi.NET 的差异

- **上游**：`Message`、`ContentBlock`、`ToolCall`、`Usage`、`StopReason` 名称一致；
- **我们**：`string | blocks` 拆成两个字段；`ToolResultMessage` 非泛型；`StopReason` 用 enum；
- **Pi.NET**：可参考它的 record/抽象类写法，但不照抄字段；冲突时以上游为准。

## 八、调优 / 扩展点

- `AssistantMessage.ThinkingLevel` 目前是字符串，S2/S4 会换成 enum；
- `ToolResultMessage.Details` 目前是 `JsonNode`，工具层可做强类型转换；
- 图片块已定义但暂不使用；`ImagesContext` / 分类 / 嵌套工具调用未移植；
- 验证方法只在边界调用；如果构造点很多，可考虑工厂方法（`SystemMessage.FromText` 等）减少误用。
